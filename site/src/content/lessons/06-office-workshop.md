# 第 6 堂：教材製作與教學輔導強化工作坊

## 基本資訊

- **時長**：60 分鐘
- **型態**：分組實作 + 交叉審查 + SOP 收斂
- **對應學習目標**：
  - 6.1 把 Agent 技術放進博幼基金會的真實幕僚工作
  - 6.2 完成從需求拆解、資料整理、Agent 產出到人工審查的完整流程
  - 6.3 用團隊協作方式設計可重複使用的教材或教學輔導工作流
  - 6.4 帶走一個回到工作現場就能試行的小型 SOP

---

## 教學定位

這一堂要讓學員練習一種新的工作方式，不只看 Agent 能不能做事：

1. 先把幕僚任務講清楚。
2. 只給 Agent 最小必要資料。
3. 把 Agent 當成草稿員、整理員、提醒員，不把最後判斷交出去。
4. 用明確規準檢查產出，最後整理成可以重複使用的 SOP。

講師開場時要把重點說白：

> 今天要比的是，誰能把教材製作或教學輔導的工作流程講清楚、做穩、做得安全。

也要先定調：今天不是要學更多指令，而是要看懂同一個任務怎麼拆給不同 Agent，最後再由人收斂判斷。

---

## 工作坊流程

| 時間 | 階段 | 目標 |
|------|------|------|
| 0–5 分鐘 | 任務重新定位 | 把最後一堂從「玩 Agent」拉回「改善幕僚工作流程」 |
| 5–13 分鐘 | 去識別化微演練 | 建立資料最小化與隱私底線 |
| 13–20 分鐘 | 任務選擇與需求拆解 | 選定場景，說清楚輸入、輸出、限制 |
| 20–30 分鐘 | 講師多 Agent Live Demo | 讓學員看見任務怎麼拆給不同 Agent，並看到可交付成果骨架 |
| 30–38 分鐘 | 學員簡化實作 | 用小組版本重做「整理 → 審查 → 交付」的基本流程 |
| 38–48 分鐘 | Rubric 交叉審查 | 由另一組檢查正確性、適配性與可執行性 |
| 48–56 分鐘 | SOP 收斂 | 把一次性操作整理成可複用流程 |
| 56–60 分鐘 | 帶走承諾 | 每組寫下兩週內要試行的一件小事 |

---

## 第一階段：任務重新定位（5 min）

**講師要說的重點**

- 博幼的幕僚工作不只是在做文件，它直接支撐教學品質、跨中心協作與學童支持。
- Agent 很適合幫忙整理、比對、起草、提醒，但不適合直接替人做教學判斷或個案決策。
- 今天重點不是學更多指令，而是看懂一個任務怎麼拆給不同 Agent，最後再由人決定能不能用。
- 今天每組都要完成三件事：
  1. 做出一版原型
  2. 說明怎麼審查原型
  3. 整理成可重複使用的 SOP

**黑板或投影片可直接放這三句話**

- 先懂任務，再下指令。
- 先去識別，再給 Agent。
- 先出草稿，再做人審。

---

## 第二階段：去識別化微演練（8 min）

### 活動目標

讓學員在真正操作前，先練習把敏感資料改寫成可以安全送進 Agent 的版本。

### 活動流程

1. 講師提供一段含有姓名、中心名稱、家庭處境與教學狀況的原始紀錄。
2. 每組用 3 分鐘把內容改寫成「可餵給 Agent 的版本」。
3. 每組互看彼此版本，找出還沒遮乾淨的地方。
4. 講師總結「最小必要輸入」原則。

### 可用的去識別化方法

- **替代法**：把姓名改成「學生 A」「教師 B」「中心 C」。
- **摘要法**：把完整敘述改成趨勢、風險或需求描述。
- **遮蔽法**：保留角色，不保留可識別細節。

### 完成標準

改寫後的文字應符合以下三點：

- 看得出任務背景
- 看不出真實身分
- 足夠支撐 Agent 完成工作

---

## 第三階段：任務選擇與需求拆解（7 min）

每組從以下場景中選一個。

| 場景 | 任務主題 | 核心產出 | 適合的小組 |
|------|---------|---------|-----------|
| A | 教學輔導異常雷達 | 需優先關注的中心、單元與協作事項 | 想從固定格式任務開始的小組 |
| B | 教材修訂任務追蹤 | 教材待修項、負責人、期限、驗收標準 | 熟悉會議整理或專案追蹤的小組 |
| C | 學習支持需求分類 | 來自家長、老師或社工的需求分類與回應方向 | 對輔導與溝通情境敏感的小組 |
| D | 跨中心教材落差分析 | 單元卡關點、補救素材方向、優先支援順序 | 喜歡比較與分析的小組 |
| E | 教材製作 Agent 工作流 | 差異化練習、教師提示語、補救教學建議 | 想直接碰教材設計的小組 |

### 每組先回答的四個問題

1. 這個任務原本最花時間的地方是什麼？
2. 哪些資料可以安全提供給 Agent？
3. 你希望 Agent 先做草稿、整理還是比對？
4. 什麼內容一定要留給人來判斷？

---

## 第四階段：講師 Live Demo 與小組轉譯實作（18 min）

這一段分兩小段走。前半段由講師示範多 Agent 協作，後半段由學員把同樣邏輯轉成自己小組可用的簡化版本。重點不是把每個工具都跑滿，而是看懂「整理 → 審查 → 交付」怎麼接起來。

### A. 講師多 Agent Live Demo（20–30 分鐘）

講師選一個匿名化場景，例如「教材修訂任務追蹤」或「跨中心教材落差分析」，現場跑一條完整鏈路。

#### 三個角色怎麼分

| 角色 | 輸入 | 輸出 | 人工決策點 |
|------|------|------|------------|
| 資料整理 Agent | 去識別化的週報、教材修訂紀錄、跨中心回報 | 結構化欄位草稿，例如待修單元、風險、待補資料、負責窗口 | 哪些資訊足夠進下一步，哪些內容其實還太模糊 |
| 審查 Agent | 資料整理 Agent 交出的欄位草稿 | 修正版欄位、缺漏提醒、待確認註記、敏感資訊檢查結果 | 哪些判斷屬於過度推論，哪些欄位必須回頭查證 |
| 交付物 Agent | 經審查的欄位資料與待確認註記 | 表格型成果骨架與簡報型成果骨架 | 哪些項目可以正式對外，哪些語句或排序要由人最後拍板 |

#### Demo 要讓學員看見的兩種成果

1. **表格型成果**：至少看到一份 Excel／CSV／追蹤表骨架，欄位可包含單元名稱、待修項目、負責人、期限、狀態、待確認事項。
2. **簡報型成果**：至少看到一份 3 頁簡報大綱：
   - 第 1 頁：本週主要發現與問題摘要
   - 第 2 頁：待修教材與追蹤節點
   - 第 3 頁：需要主管或教學組決定的事項

#### 講師操作提醒

- 一次只示範一條任務鏈，不同工具成功與否不是主角。
- 每換一個 Agent，就口頭補一句「它現在接的是什麼、交回來的是什麼」。
- Demo 結尾要停下來問學員：哪一步你願意交給 Agent，哪一步你一定要自己看。

### B. 學員簡化實作（30–38 分鐘）

各組不用重現全部 Live Demo，只要把自己選的場景拆成三段：整理、審查、交付。

### 簡化實作原則

- 一次只做一個工作目標。
- 先把輸出欄位講清楚，再要求內容。
- 先決定哪一段交給哪個 Agent，再補 prompt。
- 發現方向歪掉時，直接重開一輪，不要硬修到最後。

### 建議工作節奏

1. **第一輪**：決定三個角色各做什麼。
2. **第二輪**：先產出表格或清單骨架。
3. **第三輪**：補上內容，並標出一定要人工確認的地方。

### 本階段最低交付

每組至少要交出以下四項：

1. 一份可展示的 Agent 產出初稿。
2. 一段 80 字內的任務說明。
3. 一份欄位清楚的輸入／處理／輸出整理。
4. 一份簡單標註「這段交給哪個 Agent、哪段由人收尾」的分工表。

---

## 第五階段：Rubric 交叉審查（10 min）

每組把成果交給另一組審查。重點放在它能不能真的拿回工作現場用，語病不是這一輪的主戰場。

### 5 分制品質 Rubric

| 面向 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 教學正確性 | 有明顯概念錯誤，不能直接用 | 大致正確，但仍要逐段修 | 可進入內部審稿，只需少量調整 |
| 學童適配性 | 難度不符，沒有鷹架 | 有分層，但還不夠細 | 有先備知識、提示與補救方向 |
| 幕僚可執行性 | 沒有負責人、期限或輸出欄位 | 有清單，但追蹤性不足 | 能直接接到追蹤表或會議流程 |
| 隱私與倫理 | 含可識別或不當標籤資訊 | 已遮蔽，但標準不一 | 去識別完整，語氣穩定，不貼標籤 |
| 可追蹤性 | 看不出依據與待確認點 | 有部分來源或註記 | 有輸入來源、修改理由、待確認事項 |

### 審查後要回給對方的內容

- 一個最需要修的地方
- 一個可以保留的做法
- 一個回到工作現場前必須補上的欄位

---

## 第六階段：SOP 收斂（8 min）

這一段要把當次操作整理成下次能重做的流程。

### SOP 最少要有這六欄

1. **任務名稱**
2. **何時啟動**
3. **要準備哪些資料**
4. **Agent 做哪些事**
5. **人要做哪些最後判斷**
6. **如果改用多 Agent，哪一段交給誰**

### 講師提醒

如果學員寫出來的 SOP 只有 prompt，還不算完成。SOP 應該包含：

- 啟動時機
- 輸入資料標準
- 人工審查點
- 產出要交給誰
- 若改成多 Agent 流程，要明白寫出整理、審查、交付各由誰接手

---

## 第七階段：帶走承諾（4 min）

每組用一句話寫下回去兩週內要試行的一個小任務。

格式如下：

> 我們要在兩週內，用 Agent 先做 ________ 的第一版草稿，並由 ________ 做最後審查。

講師最後可請 2 組口頭分享，讓承諾更具體。

---

## 各場景的建議交付物

| 場景 | 建議交付物 |
|------|-----------|
| A 教學輔導異常雷達 | 異常摘要表、需支援中心清單、下週追蹤項目 |
| B 教材修訂任務追蹤 | 待辦清單、責任分工表、教材驗收標準 |
| C 學習支持需求分類 | 需求分類表、優先處理順序、回應方向草稿 |
| D 跨中心教材落差分析 | 卡關單元表、補救素材方向、優先支援排序 |
| E 教材製作 Agent 工作流 | 差異化練習、教師提示語、補救教學建議卡 |

---

## 評量重點

今天的評量不看哪一組做得最華麗，而看三件事：

1. 任務定義是否清楚。
2. 有沒有把人工審查放回流程裡。
3. 有沒有整理出可重複使用的 SOP。

如果時間不夠，優先保住這三件事，不必硬做完整 Demo。

---

## 課程總結

### 用一句話收掉今天這堂課

> Agent 先把整理、比對、提醒這些工作做出第一版，真正需要專業判斷的部分，還是留給人。

### 建議學員回去先做的小任務

- 先挑一個固定格式任務試行，不要直接碰高風險個案。
- 先建立自己的去識別化習慣，再擴大使用情境。
- 先把 Agent 當成草稿員，不要當最後簽核者。

---

## 講師備註

- 若現場學員多為教材幕僚，可優先推薦 B、D、E 場景。
- 若現場學員多為社工或中心行政，可優先推薦 A、C 場景。
- 若網路不穩，至少保住去識別化演練、需求拆解與 SOP 收斂三段，這三段不用依賴即時 API 也能完成。
- 詳細的場景資料與提示詞模板，請搭配 `docs/workshop/labs/lab-04-office-scenarios-prototype.md` 與 `docs/workshop/templates/` 內文件使用。
