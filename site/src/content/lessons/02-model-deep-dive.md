# 認識 AI 模型：Agent 的大腦運作原理

## 基本資訊

- **時長**：50 分鐘
- **型態**：講解 + 即時示範 + 小組觀察活動
- **對應學習目標**：
  - 2.1 理解語言模型的基本運作原理（文字接龍 → 推理引擎）
  - 2.2 認識當前主流模型家族及其特色差異
  - 2.3 理解模型的能力邊界與常見限制
  - 2.4 能觀察並比較不同模型在相同任務上的表現差異

## 教學流程

### 第一階段：複習與銜接（5 分鐘）

**學習重點：**

- 回顧上一堂的三層架構圖：
  ```
  Agent（智能體）
    └─ Harness（控管框架）
         └─ Model（模型）  ← 今天的主角
  ```
- 今日主題：Model 是 Agent 的智慧來源，就像人的大腦。今天要拆開這個大腦，看看裡面是怎麼運作的。
- 先說明：你不會學到數學公式，但會學到足以理解「為什麼 AI 有時候會出錯」的原理。

### 第二階段：語言模型的運作原理（15 分鐘）

**學習重點：**

#### 從「文字接龍」開始

用一個直覺化的方式理解語言模型的核心機制：

1. **文字接龍遊戲**：給 AI 一段文字，它預測下一個字是什麼
   - 輸入：「今天天氣很好，我們去」
   - 模型計算：「公園」（60%）、「逛街」（25%）、「看電影」（15%）
   - 它每次只預測一個字，但這個預測能力經過大量訓練後變得非常精準

2. 在「接下一個字」的過程中，模型學到了：
   - 語法結構（中英文都通）
   - 知識關聯（「巴黎是法國的___」→「首都」）
   - 推理邏輯（「如果 A > B 且 B > C，則 A ___ C」→「>」）
   - 這些能力不是被明確「教」的，而是從大量文字中「浮現」出來的

**概念整理：**

```
訓練資料（數兆字的文字）
        ↓
    學習「統計模式」
        ↓
    浮現出「理解能力」
        ↓
    表現為「推理能力」
```

3. **「浮現能力」（Emergent Abilities）** 是關鍵概念：
   - 當模型規模夠大、訓練資料夠多時，會突然展現出訓練目標之外的能力
   - 類比：小孩學閱讀，最初只是學認字，但讀多了就自然學會了推理和批判思考

#### 從文字生成器到推理引擎

- **早期語言模型**：只能做「合理的文字延續」，就像一個很有文采但不太會思考的人
- **現代語言模型（2024-2025）**：
  - Chain-of-Thought：會一步一步想，而不是直接跳到答案
  - Tool Use：知道自己什麼時候「不知道」，會去查資料
  - 規劃能力：能把複雜目標拆成多個步驟
- 這些推理能力讓 Model 從「聊天工具」升級為「Agent 的大腦」，它開始能思考「我該怎麼完成這個任務」

**注意：避免過度簡化**
- 模型不是真的在「思考」，它是在做非常複雜的統計預測。但這個預測精確到一個程度，看起來就像在思考了。理解這一點很重要，因為這也解釋了為什麼它會犯一些「人類不會犯的錯」。

### 第三階段：模型家族簡介（12 分鐘）

**學習重點：**

用「車廠」做比喻：每家車廠都有自己的特色車款，但都是「車」。

| 家族 | 代表模型 | 特色 | 適合場景 |
|------|---------|------|---------|
| **GPT 系列（OpenAI）** | GPT-4o, o3 | 生態最完整，工具整合最成熟 | 通用任務、商業應用 |
| **Claude 系列（Anthropic）** | Claude 4.7, Claude Sonnet | 長文本處理強、安全意識高、遵循指令精準 | 分析長文件、程式開發、需要可靠輸出 |
| **Gemini 系列（Google）** | Gemini 2.5 | 多模態能力強（文字+圖片+影片） | 多媒體理解、整合 Google 生態 |
| **開源模型** | Llama 4, Mistral, Qwen | 可自行部署、客製化、成本低 | 資料隱私要求高、需要微調、大規模部署 |

**開源 vs 閉源**

```
閉源模型（GPT, Claude, Gemini）
  優：通常能力最強、有完整的 API 和工具
  缺：資料送出去、無法客製內部運作、有使用成本

開源模型（Llama, Mistral, Qwen）
  優：可自己架設、資料不出門、可針對任務微調
  缺：需要技術能力部署、硬體成本、通常能力略遜頂級閉源
```

**Hermes Agent 的定位：**
- Hermes 是 Nous Research 的開源 Agent 框架
- 它可以搭配不同的 Model（開源或閉源），所以你選模型時有彈性
- 預設使用的模型來自同一個開源社群，強調自主性與可控制性

**實用判斷準則：**
- 需要最強能力、不在意資料外送 → 閉源模型
- 需要資料隱私、有技術團隊 → 開源模型自建
- 預算有限但想嘗試 → 開源模型 + 雲端 API

#### 與模型對話時的隱私保護

不管你用的是哪個模型，都必須了解一個重要事實：**你輸入的所有內容都會離開你的電腦**。

**資料去了哪裡？**

```
你的電腦 → 網路傳輸 → 模型公司的伺服器（可能在美國）→ 處理後回傳結果
```

這意味著：
- 你的輸入會經過網路傳輸，理論上有被攔截的風險
- 模型公司可能會暫時儲存你的輸入，部分公司會用它來訓練模型
- 即使公司宣稱不會用來訓練，資料仍然經過他們的伺服器

**絕對不要輸入的資料（紅線清單）**：

| 類型 | 具體例子 | 原因 |
|------|---------|------|
| 學童個資 | 姓名、出生日期、身分證字號、家庭住址 | 個人資料保護法規範 |
| 個案記錄 | 家訪筆記、輔導內容、家庭狀況評估 | 社工倫理與保密義務 |
| 員工個資 | 薪資、績效考核、健康紀錄 | 勞基法與隱私權保護 |
| 機密資訊 | 未公開的計畫、財務報表、捐款者資料 | 組織內部機密 |
| 帳號密碼 | API Key、登入憑證、銀行帳號 | 資訊安全基本原則 |

**安全的使用方式**：

- 用「某位國小三年級學生」代替真實姓名
- 用「數學成績從 60 分進步到 80 分」代替具體學生資料
- 先脫敏再輸入：移除姓名、身分證字號、地址等可直接識別個人的欄位
- 處理彙整與統計資料（如「全中心課輔通過率」）是安全的
- 不確定時，就不要貼進去

#### 實務技巧：如何在工作中安全使用 AI

「不能輸入真實資料」不代表「不能處理涉及個資的工作」。關鍵是先做好**去識別化（De-identification）**再送給 AI，最後再把結果對回真實資料。

**方法一：替代（Substitution）— 用代號取代真實資訊**

適用情境：需要 AI 幫你分析、整理包含個人資訊的文件。

| 替代前（原始資料） | 替代後（送給 AI） | 說明 |
|-------------------|-------------------|------|
| 王小明（中山中心） | 學生 A（中心 A） | 姓名和地點都代號化 |
| 身分證字號 A123456789 | 編號 S001 | 完全替換 |
| 住址：台北市大安區XX路12號 | 住址：（已移除） | 直接刪除 |
| 0912-345-678 | （電話已移除） | 直接刪除 |
| 李老師說小明的數學進步了 | 老師 A 說學生 A 的數學進步了 | 人物全代號化 |

**操作流程**：
1. 複製原始文件到一個新檔案（保留原件不動）
2. 用搜尋取代功能，把所有真實姓名改成代號（如：王小明 → 學生 A）
3. 移除身分證字號、電話、地址等可直接識別的欄位
4. 確認替換完成後，把這份去識別化的版本貼給 AI 處理
5. AI 回傳結果後，對照原始文件把代號換回真實姓名

**方法二：摘要（Summarization）— 只取趨勢和結論**

適用情境：需要 AI 幫你寫報告、做統整，但不需要 AI 看到個別細節。

```
❌ 不要這樣做：
「以下是本週 15 位學童的個別課輔紀錄，請幫我整理成週報：
 1. 王小明：數學月考 65 分，比上週進步 5 分...
 2. 李小華：國語聽寫錯 3 個字，需要加強...」

✅ 應該這樣做：
「本週課輔班共有 15 位學童，整體表現如下：
 - 數學：全班平均進步 3 分，其中 8 位同學進步、5 位持平、2 位退步
 - 國語：聽寫正確率約 85%，需要加強注音符號
 請幫我把以上重點整理成一段 100 字的週報摘要。」
```

**方法三：遮蔽（Masking）— 部分隱藏**

適用情境：需要 AI 理解文件格式和結構，但不需看到完整內容。

```
原始文件：
  主旨：關於陳美玲同學的家庭狀況變更
  陳美玲的父親於 3 月失業，母親目前獨自撫養三個孩子...

遮蔽後：
  主旨：關於【學生 B】的家庭狀況變更
  【學生 B】的家長於近期遭遇【經濟狀況變動】，
  目前家庭照顧資源有所調整...
```

**快速檢查清單：送出前問自己三個問題**

1. **能否從內容找到特定的人？**（姓名、特徵組合、罕見事件）→ 能的話就繼續去識別
2. **移除所有可直接識別資訊後，AI 還能完成任務嗎？** → 通常可以，AI 要的是結構和趨勢
3. **這份資料如果外洩，會對當事人造成傷害嗎？** → 會的話就加倍小心或改用摘要法

### 第四階段：模型的能力邊界（8 分鐘）

**學習重點：**

這段是整堂課最重要的實用知識：了解 AI 什麼時候會出錯。

#### 限制一：幻覺（Hallucination）

- **什麼是幻覺**：模型自信地說出聽起來合理但實際上錯誤的內容
- **為什麼會發生**：因為模型的本質是「預測最合理的下一個字」，不是「查證事實」
- **生活化比喻**：就像一個博學但愛面子的人，不知道的時候不會說「我不知道」，而是編一個聽起來很合理的答案
- **實例**：問 AI 某個不存在的研究論文，它可能會編造一篇完整的論文，包含作者、期刊名、摘要

#### 限制二：上下文窗口（Context Window）

- **什麼是上下文窗口**：模型一次能「看到」的文字量上限
- **比喻**：就像一張固定大小的桌子，你把資料放在上面讓 Agent 看，桌子放滿了，就得收掉舊的才能放新的

**Context 的三個組成部分**

上下文不是只有「你說了什麼」，而是由三個部分共同組成：

```
┌──────────────────────────────────────────────┐
│            Context（上下文）                   │
│                                              │
│  ┌────────────┐  ┌─────────────────────────┐ │
│  │ 系統提示    │  │ 對話歷史                 │ │
│  │            │  │                         │ │
│  │「你是課輔  │  │ 你：「幫我彙整週報」     │ │
│  │ 行政助理， │  │ Agent：「好的，我需要    │ │
│  │ 擅長整理   │  │   先讀取進度檔案...」    │ │
│  │ 報告...」  │  │                         │ │
│  └────────────┘  └─────────────────────────┘ │
│  ┌──────────────────────────────────────────┐ │
│  │ 工具執行結果                              │ │
│  │                                          │ │
│  │ [檔案內容：埔里中心本週進度...]            │ │
│  │ [搜尋結果：偏鄉教育最新政策...]            │ │
│  └──────────────────────────────────────────┘ │
│                                              │
│  → 這三者共享 Context Window 的總容量         │
└──────────────────────────────────────────────┘
```

- **系統提示（System Prompt）**：設定 Agent 的角色和行為規範，例如「你是課輔行政助理，擅長整理報告，注意保護學童隱私」
- **對話歷史（Conversation History）**：你跟 Agent 之間一來一往的所有訊息
- **工具執行結果（Tool Results）**：Agent 使用工具後得到的資料，例如讀到的檔案內容、搜尋到的網頁

**為什麼這很重要？**

因為 Context Window 的容量是固定的，這三個部分共享同一個空間。當對話很長、工具回傳大量資料時，Agent 可能「放不下」你最開始的指示——這時它就會開始遺忘或偏離。

- **數字感**：
  - 早期：幾千字（一篇文章）
  - 現在：十萬到數百萬字（一本到數本書）
- **對 Agent 的影響**：Agent 需要記住整個任務過程，對話太長就會忘記一開始的指示
- **對你的意義**：這就是為什麼有時候 Agent 會「忘記」你說過的話——不是它不聽話，而是桌子放不下了

> 第 4 堂課會深入探討 Context 如何影響 Agent 的表現，以及你可以用什麼策略來管理它。

#### 限制三：不確定性與不一致性

- 同一個問題問兩次，可能得到不同答案
- 模型輸出有隨機性（溫度參數 Temperature），這是特性不是 Bug
- 對 Agent 的影響：同一個任務執行兩次可能走不同的路徑
- 這也是為什麼需要 Harness：需要檢查和驗證 Agent 的輸出

#### 限制四：知識截止日期

- 模型的知識來自訓練資料，訓練完成後就「定格」了
- 除非有即時搜尋工具，否則不知道最新發生的事
- 對 Agent 的意義：Agent 需要搭配「工具」（搜尋、API）來取得即時資訊

**概念整理：四大限制一覽**

```
┌──────────────────────────────────────────┐
│           模型的能力邊界                    │
│                                          │
│  幻覺 ← 編造聽起來合理的錯誤內容          │
│  上下文 ← 一次只能記住有限內容             │
│  不確定性 ← 同一問題可能不同答案           │
│  知識截止 ← 不知道訓練之後發生的事          │
│                                          │
│  → 這些限制就是 Harness 存在的理由        │
└──────────────────────────────────────────┘
```

### 第五階段：Live Demo — 同任務不同模型（10 分鐘）

**示範步驟：**

以下用具體任務來觀察不同模型的表現差異。

**任務範例：**「請幫我分析以下學童學習進度報告，判斷哪些學童需要額外關注（高/中/低關注度），並建議後續行動。報告內容：『博幼基金會竹東中心本月課輔進度：小美（小四）數學單元測驗連續三週未達標，上課注意力不集中；小明（小六）國語成績穩定進步，但最近兩次缺席未請假；小華（小五）英文閱讀理解有明顯進步，但家長反映孩子回家後不願寫作業。』」

**觀察重點：**

1. 將同一段 prompt 分別送入 2-3 個不同模型
2. 並排對比，觀察以下面向：
   - 回答的**結構**是否不同？（有人列點、有人敘述）
   - 判斷的**關注程度**是否一致？
   - **建議的行動**有什麼差異？
   - 有沒有出現**幻覺**？（例如編造不存在的學童背景資料）
   - **語氣和溫度**的差異

3. 討論問題：
   - 「哪個回答你覺得最好？為什麼？」
   - 「如果這是 Agent 在自動分析學童學習狀況，你會擔心什麼？」
   - 「這也說明為什麼 Agent 需要 Harness——需要一個機制來檢查 Model 的輸出是否合理，尤其是涉及學童的判斷」

## 關鍵概念

1. **語言模型的核心機制**：透過預測下一個字來生成回應，在這個過程中浮現出推理、規劃等高階能力
2. **浮現能力（Emergent Abilities）**：模型規模夠大時，自然展現出超越訓練目標的能力
3. **模型家族的定位差異**：閉源模型能力強但受限，開源模型可自控但需技術投入
4. **模型的四大限制**：幻覺、上下文窗口、不確定性、知識截止，這些是 Harness 必須處理的問題
5. **Context 由三部分組成**：系統提示（角色設定）＋對話歷史（你跟 Agent 的對話）＋工具結果（Agent 查到的資料），三者共享 Context Window 的總容量
6. 好的 Agent 不只需要好的 Model，還需要 Harness 來控管和驗證

## 延伸活動（若有餘裕時間）

- **模型猜猜看遊戲**（5 分鐘）：展示 4-5 段 AI 回答，猜猜是哪個模型生成的。答案不那麼重要，重點是觀察回答風格的差異
- **幻覺偵探**（5 分鐘）：閱讀幾段 AI 生成的文字，其中有些包含幻覺內容，試著找出來。這個練習可以培養「不要無條件相信 AI 輸出」的意識
- **「你會怎麼選？」情境討論**（5 分鐘）：想像 3 個不同的工作情境（例如：分析學童學習資料、撰寫課輔教材、翻譯國外教育研究報告），思考在每個情境下會選擇閉源還是開源模型，為什麼
