# 認識 AI 模型：Agent 的大腦運作原理

## 基本資訊

- **時長**：50 分鐘
- **型態**：講解 + 即時示範 + 小組觀察活動
- **對應學習目標**：
  - 2.1 理解語言模型的基本運作原理（文字接龍 → 推理引擎）
  - 2.2 認識當前主流模型家族及其特色差異
  - 2.3 理解模型的能力邊界與常見限制
  - 2.4 能觀察並比較不同模型在相同任務上的表現差異

---

## 教學流程

### 第一階段：複習與銜接（5 分鐘）

**學習重點：**

- 回顧上一堂的三層架構圖：
  ```
  Agent（智能體）
    └─ Harness（控管框架）
         └─ Model（模型）  ← 今天的主角
  ```
- 今日主題：Model 是 Agent 的智慧來源，就像人的大腦。今天要拆開這個大腦，看看裡面是怎麼運作的。
- 先說明：你不會學到數學公式，但會學到足以理解「為什麼 AI 有時候會出錯」的原理。

### 第二階段：語言模型的運作原理（15 分鐘）

**學習重點：**

#### 從「文字接龍」開始

用一個直覺化的方式理解語言模型的核心機制：

1. **文字接龍遊戲**：給 AI 一段文字，它預測下一個字是什麼
   - 輸入：「今天天氣很好，我們去」
   - 模型計算：「公園」（60%）、「逛街」（25%）、「看電影」（15%）
   - 它每次只預測一個字，但這個預測能力經過大量訓練後變得非常精準

2. 在「接下一個字」的過程中，模型學到了：
   - 語法結構（中英文都通）
   - 知識關聯（「巴黎是法國的___」→「首都」）
   - 推理邏輯（「如果 A > B 且 B > C，則 A ___ C」→「>」）
   - 這些能力不是被明確「教」的，而是從大量文字中「浮現」出來的

**概念整理：**

```
訓練資料（數兆字的文字）
        ↓
    學習「統計模式」
        ↓
    浮現出「理解能力」
        ↓
    表現為「推理能力」
```

3. **「浮現能力」（Emergent Abilities）** 是關鍵概念：
   - 當模型規模夠大、訓練資料夠多時，會突然展現出訓練目標之外的能力
   - 類比：小孩學閱讀，最初只是學認字，但讀多了就自然學會了推理和批判思考

#### 從文字生成器到推理引擎

- **早期語言模型**：只能做「合理的文字延續」，就像一個很有文采但不太會思考的人
- **現代語言模型（2024-2025）**：
  - Chain-of-Thought：會一步一步想，而不是直接跳到答案
  - Tool Use：知道自己什麼時候「不知道」，會去查資料
  - 規劃能力：能把複雜目標拆成多個步驟
- 這些推理能力讓 Model 從「聊天工具」升級為「Agent 的大腦」，它開始能思考「我該怎麼完成這個任務」

**注意：避免過度簡化**
- 模型不是真的在「思考」，它是在做非常複雜的統計預測。但這個預測精確到一個程度，看起來就像在思考了。理解這一點很重要，因為這也解釋了為什麼它會犯一些「人類不會犯的錯」。

### 第三階段：模型家族簡介（12 分鐘）

**學習重點：**

用「車廠」做比喻：每家車廠都有自己的特色車款，但都是「車」。

| 家族 | 代表模型 | 特色 | 適合場景 |
|------|---------|------|---------|
| **GPT 系列（OpenAI）** | GPT-4o, o3 | 生態最完整，工具整合最成熟 | 通用任務、商業應用 |
| **Claude 系列（Anthropic）** | Claude 4.7, Claude Sonnet | 長文本處理強、安全意識高、遵循指令精準 | 分析長文件、程式開發、需要可靠輸出 |
| **Gemini 系列（Google）** | Gemini 2.5 | 多模態能力強（文字+圖片+影片） | 多媒體理解、整合 Google 生態 |
| **開源模型** | Llama 4, Mistral, Qwen | 可自行部署、客製化、成本低 | 資料隱私要求高、需要微調、大規模部署 |

**開源 vs 閉源**

```
閉源模型（GPT, Claude, Gemini）
  優：通常能力最強、有完整的 API 和工具
  缺：資料送出去、無法客製內部運作、有使用成本

開源模型（Llama, Mistral, Qwen）
  優：可自己架設、資料不出門、可針對任務微調
  缺：需要技術能力部署、硬體成本、通常能力略遜頂級閉源
```

**Hermes Agent 的定位：**
- Hermes 是 Nous Research 的開源 Agent 框架
- 它可以搭配不同的 Model（開源或閉源），所以你選模型時有彈性
- 預設使用的模型來自同一個開源社群，強調自主性與可控制性

**實用判斷準則：**
- 需要最強能力、不在意資料外送 → 閉源模型
- 需要資料隱私、有技術團隊 → 開源模型自建
- 預算有限但想嘗試 → 開源模型 + 雲端 API

### 第四階段：模型的能力邊界（8 分鐘）

**學習重點：**

這段是整堂課最重要的實用知識：了解 AI 什麼時候會出錯。

#### 限制一：幻覺（Hallucination）

- **什麼是幻覺**：模型自信地說出聽起來合理但實際上錯誤的內容
- **為什麼會發生**：因為模型的本質是「預測最合理的下一個字」，不是「查證事實」
- **生活化比喻**：就像一個博學但愛面子的人，不知道的時候不會說「我不知道」，而是編一個聽起來很合理的答案
- **實例**：問 AI 某個不存在的研究論文，它可能會編造一篇完整的論文，包含作者、期刊名、摘要

#### 限制二：上下文窗口（Context Window）

- **什麼是上下文窗口**：模型一次能「看到」的文字量上限
- **比喻**：就像一個人只能記住最近 N 頁的書，之前的內容就忘了
- **數字感**：
  - 早期：幾千字（一篇文章）
  - 現在：十萬到數百萬字（一本到數本書）
- **對 Agent 的影響**：Agent 需要記住整個任務過程，對話太長就會忘記一開始的指示

#### 限制三：不確定性與不一致性

- 同一個問題問兩次，可能得到不同答案
- 模型輸出有隨機性（溫度參數 Temperature），這是特性不是 Bug
- 對 Agent 的影響：同一個任務執行兩次可能走不同的路徑
- 這也是為什麼需要 Harness：需要檢查和驗證 Agent 的輸出

#### 限制四：知識截止日期

- 模型的知識來自訓練資料，訓練完成後就「定格」了
- 除非有即時搜尋工具，否則不知道最新發生的事
- 對 Agent 的意義：Agent 需要搭配「工具」（搜尋、API）來取得即時資訊

**概念整理：四大限制一覽**

```
┌──────────────────────────────────────────┐
│           模型的能力邊界                    │
│                                          │
│  幻覺 ← 編造聽起來合理的錯誤內容          │
│  上下文 ← 一次只能記住有限內容             │
│  不確定性 ← 同一問題可能不同答案           │
│  知識截止 ← 不知道訓練之後發生的事          │
│                                          │
│  → 這些限制就是 Harness 存在的理由        │
└──────────────────────────────────────────┘
```

### 第五階段：Live Demo — 同任務不同模型（10 分鐘）

**示範步驟：**

以下用具體任務來觀察不同模型的表現差異。

**任務範例：**「請幫我分析以下學童學習進度報告，判斷哪些學童需要額外關注（高/中/低關注度），並建議後續行動。報告內容：『博幼基金會竹東中心本月課輔進度：小美（小四）數學單元測驗連續三週未達標，上課注意力不集中；小明（小六）國語成績穩定進步，但最近兩次缺席未請假；小華（小五）英文閱讀理解有明顯進步，但家長反映孩子回家後不願寫作業。』」

**觀察重點：**

1. 將同一段 prompt 分別送入 2-3 個不同模型
2. 並排對比，觀察以下面向：
   - 回答的**結構**是否不同？（有人列點、有人敘述）
   - 判斷的**關注程度**是否一致？
   - **建議的行動**有什麼差異？
   - 有沒有出現**幻覺**？（例如編造不存在的學童背景資料）
   - **語氣和溫度**的差異

3. 討論問題：
   - 「哪個回答你覺得最好？為什麼？」
   - 「如果這是 Agent 在自動分析學童學習狀況，你會擔心什麼？」
   - 「這也說明為什麼 Agent 需要 Harness——需要一個機制來檢查 Model 的輸出是否合理，尤其是涉及學童的判斷」

## 關鍵概念

1. **語言模型的核心機制**：透過預測下一個字來生成回應，在這個過程中浮現出推理、規劃等高階能力
2. **浮現能力（Emergent Abilities）**：模型規模夠大時，自然展現出超越訓練目標的能力
3. **模型家族的定位差異**：閉源模型能力強但受限，開源模型可自控但需技術投入
4. **模型的四大限制**：幻覺、上下文窗口、不確定性、知識截止，這些是 Harness 必須處理的問題
5. 好的 Agent 不只需要好的 Model，還需要 Harness 來控管和驗證

## 延伸活動（若有餘裕時間）

- **模型猜猜看遊戲**（5 分鐘）：展示 4-5 段 AI 回答，猜猜是哪個模型生成的。答案不那麼重要，重點是觀察回答風格的差異
- **幻覺偵探**（5 分鐘）：閱讀幾段 AI 生成的文字，其中有些包含幻覺內容，試著找出來。這個練習可以培養「不要無條件相信 AI 輸出」的意識
- **「你會怎麼選？」情境討論**（5 分鐘）：想像 3 個不同的工作情境（例如：分析學童學習資料、撰寫課輔教材、翻譯國外教育研究報告），思考在每個情境下會選擇閉源還是開源模型，為什麼
