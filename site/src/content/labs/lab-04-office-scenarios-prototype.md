# Lab 4：幕僚工作流實作（一）— 從需求到原型

## 基本資訊

- **所屬課程**：Hermes Agent 全天實作工作坊
- **Lab 編號**：Lab 4
- **時長**：60 分鐘
- **型態**：分組實作
- **位置**：下午場第一個單元
- **銜接關係**：承接上午的 Hermes 安裝、工具使用與自動化流程練習，為最後一堂工作坊的交叉審查與 SOP 收斂先做出第一版原型
- **核心目標**：讓學員把一個博幼基金會幕僚工作情境拆成可執行需求，完成資料準備、Agent 操作與第一版輸出

## 分組與角色

- 全班分為 4 組，每組 4–6 人
- 每組至少有三個角色：
  - **流程整理者**：釐清任務與欄位
  - **Hermes 操作員**：輸入任務、觀察 Agent 行為
  - **記錄者**：記下 prompt、修改決策與待修問題
- 若人數足夠，可再加一位：
  - **審查者**：專門負責檢查資料是否去識別化、輸出是否可用

## 教學流程

| 時間 | 階段 | 活動流程 |
|------|------|----------|
| 0–5 分鐘 | 任務說明與分工 | 確認組員角色與場景 |
| 5–12 分鐘 | 去識別化微演練 | 把原始資料改寫成可送進 Agent 的版本 |
| 12–20 分鐘 | 需求拆解 | 定義輸入、輸出、限制與人工審查點 |
| 20–42 分鐘 | 第一版原型實作 | 用 Hermes 完成第一版流程 |
| 42–52 分鐘 | 內部檢查與修正 | 用檢查表回頭看輸出 |
| 52–60 分鐘 | 收斂交付物 | 留下成果、問題與下一步 |

## 本 Lab 的交付標準

每組在 60 分鐘結束前，至少要交出以下四項：

1. 一句話說清楚這個場景要解決的工作問題。
2. 一份可展示的第一版原型成果。
3. 一張簡短說明，列出輸入資料、處理步驟、輸出結果。
4. 一份下個階段可繼續優化的迭代清單。

---

## 幕僚工作流視角

這個 Lab 要先找出哪些工作適合交給 Agent 做第一版，不把它當萬能助手。

適合先交給 Agent 的工作：

- 統一格式
- 摘要與重組
- 比對差異
- 提取待辦
- 起草教學素材

不適合直接交給 Agent 定案的工作：

- 個案判斷
- 教學決策定稿
- 敏感資訊處理
- 對外正式回覆

## 隱私保護提醒

> **這些場景涉及學童資料、家長通訊、個案記錄與跨中心追蹤。操作時一律使用課程提供的範例資料，不輸入真實姓名、聯絡方式或可識別個案細節。**

### 最小必要輸入原則

- 不需要姓名時，就不要給姓名。
- 不需要完整故事時，就只給任務相關片段。
- 不需要中心名稱時，就改成中心 A、中心 B。
- 若不確定某段是否敏感，就先拿掉再說。

---

## 微活動：去識別化演練

### 活動目標

在真正操作前，先練習把原始內容改寫成可安全送進 Agent 的版本。

### 活動流程

1. 講師提供一段原始資料。
2. 每組在 3 分鐘內做第一輪改寫。
3. 小組互相檢查是否還留有姓名、家庭資訊、特殊身份標籤。
4. 完成後才進入場景實作。

### 範例

**原始版本**

> 埔里中心的小安最近連續缺席，母親住院，由祖母照顧。數學除法單元落後兩週，導師希望社工和特教一起評估支持方式。

**可送進 Agent 的版本**

> 中心 A 有一名學童近期連續缺席，家庭照顧狀況變動中。數學某單元落後兩週，現場希望教學、社工與特教一起評估支持方式。

### 自我檢查

- 是否還能辨識出真實身分？
- 有沒有保留完成任務必須知道的事實？
- 改寫後是否仍能支撐摘要、分類或規劃工作？

## 場景總覽

| 場景 | 任務主題 | 核心能力 | 第一版輸出 |
|------|---------|---------|-----------|
| A | 教學輔導異常雷達 | 彙整、標記風險、排序 | 異常摘要表與追蹤清單 |
| B | 教材修訂任務追蹤 | 結構化、待辦擷取、協作追蹤 | 待修項清單與驗收標準 |
| C | 學習支持需求分類 | 分類、優先級判斷、回應方向 | 需求分類表與回覆方向 |
| D | 跨中心教材落差分析 | 比較、整理、補救建議 | 單元落差表與支援順序 |

不管選哪個場景，都先做下面四步：

1. 寫一句話定義任務。
2. 列出輸入欄位。
3. 列出輸出欄位。
4. 指定哪一段一定要人工檢查。

3. ...

另外請標記：
- 哪些地方需要人工確認
- 哪些內容涉及敏感資訊，不應直接對外使用

## 場景 A：教學輔導異常雷達

### 場景目標

把各中心週進度中的風險與求助訊號整理出來，讓教育處或教學組長知道本週先要看哪裡。

### 建議拆解方式

- **使用者**：教育處、教學組長
- **輸入**：各中心進度回報、學童出席、需協助事項
- **輸出**：異常摘要表、優先關注清單、下週追蹤項目
- **成功標準**：能快速看出哪個中心、哪個單元、哪個協作需求要先處理

### 測試資料

```bash
mkdir -p ~/workshop-scenario-a
cat > ~/workshop-scenario-a/center-a.txt << 'EOF'
中心 A 第 21 週回報
- 四年級數學：分數加減單元進度落後一週，3 位學童測驗未達標
- 五年級國語：閱讀理解完成，整體穩定
- 需協助事項：需要一份分數概念補救教材
- 特殊狀況：1 名學童連續兩週缺席，已由社工關心
EOF

cat > ~/workshop-scenario-a/center-b.txt << 'EOF'
中心 B 第 21 週回報
- 六年級數學：速率單元初教完成，2 位學童對公式仍不穩
- 三年級國語：造句練習完成
- 需協助事項：希望有可視化教具建議
- 特殊狀況：無重大異常
EOF

cat > ~/workshop-scenario-a/center-c.txt << 'EOF'
中心 C 第 21 週回報
- 四年級數學：分數加減單元落後兩週，4 位學童需個別補救
- 國一英文：過去式句型進行中
- 需協助事項：需要低門檻複習素材與教學順序建議
- 特殊狀況：家長回饋作業壓力偏高
EOF
```

### 提示詞模板

```text
請讀取 ~/workshop-scenario-a/center-a.txt、center-b.txt、center-c.txt，
整理成「教學輔導異常雷達」。

輸出欄位：
1. 各中心本週重點
2. 異常項目清單
3. 建議優先處理順序
4. 下週追蹤事項

如果資料不足，請標記待確認，不要自行補完。
將結果存到 ~/workshop-scenario-a/teaching-radar.md
```

### 自我檢查

- 有沒有把一般進度和異常訊號分開？
- 有沒有整理出「先處理什麼」而不只是重抄原文？
- 有沒有把需要教材支援的地方單獨標出來？

## 場景 B：教材修訂任務追蹤

### 場景目標

把會議中提到的教材修訂工作整理成能追的清單，不只停在摘要。

### 建議拆解方式

- **使用者**：教學組長、教材幕僚
- **輸入**：教學會議紀錄、試用回饋、教材待修事項
- **輸出**：待修項清單、負責人、期限、驗收標準
- **成功標準**：看完就知道誰要改什麼、何時交、怎麼算完成

### 測試資料

```bash
mkdir -p ~/workshop-scenario-b
cat > ~/workshop-scenario-b/material-meeting.txt << 'EOF'
教材修訂會議 2026/05/21
- 六年級數學「速率」單元需要重寫例題順序，避免一次塞太多概念。
- 竹東中心回饋：分數乘法的圖像示意有幫助，建議擴充到新版本。
- 林老師負責六月第一週前完成速率單元初稿。
- 陳老師負責補上三年級國語閱讀圖片輔助素材。
- 驗收時要確認：難度分層、提示語、練習量是否合理。
- 下次會議要檢查：試教回饋、學童常見錯誤是否下降。
EOF
```

### 提示詞模板

```text

4. 截止日期
5. 驗收標準
6. 下次會議要確認的事項

將結果存到 ~/workshop-scenario-b/material-task-board.md
```

### 自我檢查

- 是否把「待修項」和「背景討論」分開？
- 驗收標準有沒有具體，不只是寫「修好」？
- 哪些欄位還需要人工補資料？

## 場景 C：學習支持需求分類

### 場景目標

把來自家長、老師或社工的訊息先做第一輪分類，減少人工從零判讀的時間。

### 建議拆解方式

- **使用者**：社工、中心行政、教學幕僚
- **輸入**：家長來信、教師回饋、協作需求
- **輸出**：需求分類、優先級、回應方向、需轉介對象
- **成功標準**：能快速分出誰先處理、誰最後定案

### 測試資料

```bash
mkdir -p ~/workshop-scenario-c
cat > ~/workshop-scenario-c/message-01.txt << 'EOF'
家長回饋：孩子最近不想去學校，也開始排斥到課輔班，家裡不確定是功課壓力還是同儕問題，希望有人協助。
EOF

cat > ~/workshop-scenario-c/message-02.txt << 'EOF'
教師回饋：四年級數學分數單元有多位學童卡關，希望教材組能提供更低門檻的複習素材。
EOF

cat > ~/workshop-scenario-c/message-03.txt << 'EOF'
社工回饋：某中心近期有 2 名學童家庭照顧狀況變動，建議教學安排保留彈性，不要一次給太多書寫作業。
EOF
```

### 提示詞模板

```text
請讀取 ~/workshop-scenario-c/message-01.txt、message-02.txt、message-03.txt，
整理成「學習支持需求分類表」。

輸出欄位：
1. 訊息來源
2. 需求類型
3. 優先級
4. 建議由誰回應
5. 建議回應方向
6. 是否需要後續追蹤

將結果存到 ~/workshop-scenario-c/support-needs.md
```

### 自我檢查

- 涉及學童安全或情緒的訊息，有沒有被標成高優先？
- 是否清楚標出誰適合回應：社工、教學、特教或行政？
- 有沒有把猜測和事實分開？

## 場景 D：跨中心教材落差分析

### 場景目標

把不同中心對同一單元的進度與卡關點整理在一起，協助教材組判斷先支援哪裡。

### 建議拆解方式

- **使用者**：教材幕僚、教育處專員
- **輸入**：各中心進度表、試教觀察、常見錯誤
- **輸出**：落差表、卡關點摘要、補救素材方向
- **成功標準**：看得出共通問題，也看得出個別中心差異

## 場景 E：教材製作 Agent 工作流

### 場景目標

讓 Agent 先做教材草稿，再由人檢查難度、鷹架與語氣，建立一個可重複使用的教材製作流程。

### 建議拆解方式

- **使用者**：教材組、教學組長、課輔老師
- **輸入**：教學目標、學童常見錯誤、既有教材片段
- **輸出**：差異化練習、教師提示語、補救教學建議卡
- **成功標準**：能做出「基礎／標準／挑戰」三種層次，且看得出教學意圖

### 測試資料

```bash
mkdir -p ~/workshop-scenario-e
cat > ~/workshop-scenario-e/material-brief.txt << 'EOF'
單元：國小四年級數學－分數加減
教學目標：理解分數加減的意義，能處理同分母與簡單異分母題型。
常見錯誤：
- 不知道何時需要通分
- 把分子和分母直接相加
- 看到文字題就不知道要用加法還是減法
既有教材片段：
- 現行講義先教規則，再做 12 題演算題
- 老師回饋：練習量多，但示意圖太少，弱勢學童容易放棄
EOF
```

### 提示詞模板

```text
請讀取 ~/workshop-scenario-e/material-brief.txt，
協助產出一份「教材製作第一版草稿」。

請輸出：
1. 先備知識提醒
2. 基礎版練習 3 題
3. 標準版練習 3 題
4. 挑戰版練習 2 題
5. 教師提示語
6. 常見錯誤診斷表
7. 補救教學建議

要求：
- 不要用艱深語氣
- 題目要能看出分層
- 如果資料不足，標記待確認

將結果存到 ~/workshop-scenario-e/material-draft.md
```

### 自我檢查

- 題目分層是否真的不同，不只是改數字？
- 教師提示語是否能幫助現場帶領，而不只是重寫答案？
- 補救建議是否對應到常見錯誤？

### 延伸挑戰

若時間夠，再要求 Hermes 多做兩件事：

1. 幫每一層練習補上 1 句教學提醒。
2. 把現有教材的問題整理成「下次改版要先修什麼」。

## 關鍵概念

| 概念 | 說明 |
|------|------|
| 需求分析 | 先釐清使用者、痛點、輸入與輸出，再開始操作 Agent |
| 原型思維 | 第一版只求可運作，不求一步到位 |
| 最小必要輸入 | 只給完成任務必須知道的資料，其他不送 |
| 結構化輸出 | 先把欄位定清楚，後續才容易比較、追蹤與擴充 |
| 人工審查點 | 把最後判斷留給人，不讓 Agent 直接定案 |
| 迭代準備 | 留下問題清單，才能在下一個階段有方向地優化 |
