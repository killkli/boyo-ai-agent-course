# 講師教學指引 — 辦公室 AI Agent 實戰入門

> 供講師備課與授課參考，涵蓋課前準備、教學設計理念、各堂教學要點、Demo 操作手冊、常見問題排解及評量建議。

## 一、課前準備

### 1.1 環境準備

#### 講師設備

- 筆記型電腦（建議 macOS，Demo 較順暢）
- 外接螢幕或投影連線
- 穩定的網路連線（優先使用有線網路）
- 螢幕錄影軟體（OBS 或 QuickTime，備用於 Demo 失敗時播放預錄影片）

#### 軟體環境

- [ ] Python 3.11+ 已安裝
- [ ] Hermes Agent 已安裝且可正常運作（`hermes --version`）
- [ ] 至少三個 AI 平台的 API Key 已設定（OpenAI、Anthropic、Google）
- [ ] VS Code 已安裝，安裝 Python 延伸模組
- [ ] 終端機字體調大（建議 24pt 以上），確保後排學員可閱讀
- [ ] 瀏覽器已登入 ChatGPT、Claude、Gemini 網頁介面

#### 場地確認

- [ ] 投影設備正常運作
- [ ] 學員 Wi-Fi 可用（建議測試 20+ 人同時連線的頻寬）
- [ ] 每位學員有桌面空間放置筆電
- [ ] 延長線或插座充足（至少每兩人一個插座）

### 1.2 帳號與 API 準備

- 準備一組備用 API Key（用於協助無法完成設定的學員）
- 確認 API 帳號額度充足（建議預估每位學員課堂使用約 $0.5–1 USD）
- 如有課堂共用帳號，請提前測試額度是否足夠

### 1.3 Demo 腳本準備

- 準備每個 Demo 的預錄影片（網路不穩時的備案）
- Demo 腳本詳見下方「Demo 操作手冊」段落
- 所有 Demo 的輸入提示詞和預期輸出請預先測試過

### 1.4 講義與教材

- 課程簡報檔（PPT / PDF）
- 實作指引手冊（紙本或線上版）
- 課後資源包（已上線的線上教材連結）

### 1.5 幕僚版資料包

若本次班級重點是「教材製作以及教學輔導強化」幕僚單位，講師至少要準備以下資料：

- 一份教材修訂會議紀錄
- 一份跨中心進度差異資料
- 一份學童常見錯誤或補救需求摘要
- 一份匿名化後的家長或社工回饋片段
- 一份教材品質檢查表或審稿欄位範例

如果主辦單位能在課前提供真實工作樣態，請先協助他們做去識別化；如果無法提供，講師要自行準備同語境的模擬資料，不要臨時拿通用企業案例頂替。

## 一之一、授課對象背景：博幼基金會

### 組織簡介

博幼基金會（Boyo Social Welfare Foundation）成立於 2002 年，由李家同校長創辦，是台灣深耕偏鄉教育的指標性 NGO。2025 年全台已設立 17 處課輔中心，服務超過 2,400 位偏鄉弱勢學童。基金會的使命是「教育脫貧，讓知識帶希望回家」，透過免費課後輔導與客製化學習安排，每年為約 3,000 名兒童提升學業成績，協助他們翻轉人生。

博幼的服務策略圍繞三大主軸：教育支持、社工輔導、畢業生追蹤。課輔班聘請專職教師進行教學輔導，因材施教，為每位學童量身打造學習計畫。近年也積極推動數位教學合作（與臺南大學）、偏鄉特教早療實驗計畫，並培訓在地人成為課輔老師，補足偏鄉師資缺口。緯創人文基金會為重要合作夥伴。

本課程係應博幼基金會邀約，為其員工設計 AI 增能培訓。講師在備課與授課時，應將博幼的組織使命與服務場景融入教材，讓學員感受到 AI 工具與自身工作的直接關聯。

### 學員背景分析

- 多數學員為課輔老師、社工師、行政人員、特教老師，非技術背景。他們的專業在於教育與社會工作，而非資訊科技。
- 日常工作中包含大量重複性行政任務：每週彙整各課輔中心的進度週報、整理教學會議記錄、回覆與分類家長聯繫訊息、追蹤學童學習進度與課輔計畫執行狀況。
- 對 AI 的認知可能停留在「聽過 ChatGPT」的層次，多數學員沒有實際使用經驗，更談不上理解 Agent、Prompt Engineering 等概念。
- 工作環境多位於偏鄉，網路頻寬與設備資源可能有限。部分課輔中心的網路連線品質不穩定，教室中的電腦設備也較為老舊。

### 教學調整建議

針對博幼學員的特性，講師在授課時應注意以下調整：

- **範例場景全面替換**：所有課程範例應改用博幼的業務場景，例如課輔中心週報彙整、學童學習進度分析、家長溝通記錄整理、課輔計畫進度監控等。避免使用通用企業場景（如財報分析、客戶管理），降低學員的距離感。
- **放慢技術操作速度**：每個操作步驟多停留，確認多數學員跟上後再往下走。終端機畫面字體務必放大，指令操作時逐行說明。
- **強調「AI 幫你省時間陪孩子」的價值主張**：博幼學員的核心工作是陪伴與教育孩子。講師應將 AI 工具定位為「幫你處理行政雜務，讓你把時間留給孩子」，而非追求技術本身的精進。
- **準備離線備案**：偏鄉網路可能不穩，每個 Demo 都要有預錄影片或截圖備案。API 設定環節準備共用帳號或預先設定好的環境，避免網路問題拖住課程進度。

### 若本次以幕僚單位為主，講師要再多做三件事

1. **把最後一堂定位成工作流工作坊**：讓教材幕僚、教學組長、社工或行政人員帶走可重複使用的做法，不要把重點放在展示 Agent 多厲害。
2. **先守住資料底線**：在正式操作前，先做一次去識別化練習，讓學員知道哪些內容不能直接送進模型。
3. **要求每組留下 SOP**：如果學員最後只交出 prompt，還不夠。至少要留下任務名稱、輸入資料、Agent 動作、人工審查點與交付對象。

### 現場引導話術

以下幾句話很實用，講師可直接照用：

- 「先不要急著問 Agent 會不會做，先講清楚你要它幫你省哪一段時間。」
- 「今天先把草稿交給 Agent，最後判斷還是在人手上。」
- 「如果這段內容明天要進正式教材或個案流程，就一定要有人做最後判斷。」
- 「資料不乾淨，後面做再多都只是補破洞。」

## 二、教學設計理念

### 2.1 為什麼用 Model-Agent-Harness 三層架構？

問題：多數學員對 AI 的理解停留在「ChatGPT 就是 AI」的層次，缺乏架構性思考。

三層架構提供一個清晰的認知框架：

| 層級 | 角色 | 比喻 |
|------|------|------|
| Model | 智慧引擎，負責理解和生成 | 大腦 |
| Harness | 控管框架，負責工具管理、安全限制、流程編排 | 公司的制度與流程 |
| Agent | 面向使用者的完整應用，結合 Model + Harness + Tools + Memory | 一位遵守公司制度的員工 |

教學效益：
- 學員能清楚理解「為什麼需要 Harness」：模型本身不具備工具使用、記憶、安全控制等能力
- 學員能理解「Agent 不等於模型」：更換模型不需要重寫整個 Agent
- 為後續學習其他框架打下概念基礎

### 2.2 為什麼選擇 Hermes Agent？

| 考量 | Hermes Agent 的優勢 |
|------|---------------------|
| 安裝簡易度 | 一行指令安裝，無需複雜環境配置 |
| 學習曲線 | Python-first，設定檔簡潔，對初學者友善 |
| 功能完整性 | 自學習迴圈、跨平台、排程、子代理，涵蓋 Agent 核心概念 |
| 授權 | MIT 授權，學員可自由使用和修改 |
| 模型支援 | 支援 200+ 模型，學員可使用自己偏好的 API |
| 社群 | 活躍的 Discord 社群和持續更新 |

### 2.3 教學策略

- 做中學：50% 講授 + 30% 實作 + 20% 討論
- 漸進複雜化：從概念到模型，到 Harness，到 Agent，到實作
- 真實場景驅動：所有範例使用辦公室場景，降低距離感
- 容錯設計：每個實作環節準備備案（預錄 Demo、共用帳號）

## 三、各堂教學要點和時間管理建議

### 第 1 堂：AI 生態系概覽（09:00–09:50）

核心目標：建立三層架構的全貌理解

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 09:00–09:10 | 開場、課程介紹、學員背景調查 | 講授 | 快速了解學員組成，調整後續深度 |
| 09:10–09:25 | 從 ChatGPT 到 Agent 的演進 | 講授 | 用時間線圖呈現發展脈絡 |
| 09:25–09:40 | 三層架構介紹（Model → Harness → Agent） | 講授 | 使用比喻：大腦、制度、員工 |
| 09:40–09:50 | 分組討論：你工作中的 AI 使用現況 | 討論 | 每 3–4 人一組，了解學員痛點 |

講師提醒：
- 開場的前 10 分鐘決定了學員對課程的期望，務必清楚說明「本課程能學到什麼、不能學到什麼」
- 學員背景調查很重要：如果多數人有程式經驗，可以加速基礎段落；反之需放慢

### 第 2 堂：認識 AI 模型（10:00–10:50）

核心目標：理解模型的能力與限制

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 09:50–10:05 | 語言模型基礎原理（Token、上下文、溫度） | 講授 | 用 Tokenizer 互動展示 Token 概念 |
| 10:05–10:15 | 主要模型家族介紹（GPT、Claude、Gemini、開源模型） | 講授 | 重點在差異而非技術細節 |
| 10:15–10:40 | Demo：不同模型執行同一任務 | Demo | 詳見下方 Demo 手冊 |
| 10:40–10:50 | 討論：模型能力邊界與選擇考量 | 討論 | 引導學員思考成本、速度、品質的取捨 |

### 第 3 堂：Harness 控管框架（11:00–11:50）

核心目標：理解 Harness 為什麼存在、做了什麼

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 11:00–11:15 | 為什麼需要 Harness（模型不能做什麼） | 講授 | 列舉模型限制：無上網、無檔案存取、無記憶、無安全邊界 |
| 11:15–11:30 | Harness 的核心功能（工具管理、記憶、安全、流程） | 講授 | 配合架構圖 |
| 11:30–11:45 | 程式碼導讀：Claude Code 的 QueryEngine vs Hermes 的 AIAgent | 講授 | 展示兩種 Harness 實作的核心程式碼片段 |
| 11:45–11:50 | 重點摘要 | 講授 | 強調「模型提供智慧，Harness 提供控制」 |

講師提醒：
- 這是課程概念最密集的一段，避免過度技術化
- 程式碼導讀不需要學員看懂每一行，重點是理解「設計意圖」

### 第 4 堂：Agent 解剖學（13:00–13:50）

核心目標：理解 Agent 的組成要素

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 13:00–13:15 | Agent = Model + Harness + Tools + Memory | 講授 | 用「一位員工」的比喻貫穿 |
| 13:15–13:25 | 工具系統設計（什麼是工具、如何定義工具） | 講授 | 展示幾個工具定義的範例 |
| 13:25–13:35 | 記憶機制（短期 vs 長期、自學習迴圈） | 講授 | 強調 Hermes 的自學習特色 |
| 13:35–13:45 | 安全性考量（沙箱、權限、資料保護） | 講授 | 特別強調企業使用時的注意事項 |
| 13:45–13:50 | 綜合問答 | Q&A | 確認學員理解後才進入實作 |

### 第 5 堂：Hermes Agent 實作（14:00–14:50）

核心目標：完成第一個可運作的 Agent

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 14:00–14:10 | 安裝 Hermes Agent | 實作 | 講師帶領逐步操作，確認每位學員完成 |
| 14:10–14:20 | 完成第一個任務（CLI 對話） | 實作 | 使用簡單任務建立信心 |
| 14:20–14:35 | 啟用工具並觀察行為 | 實作 | 詳見下方 Demo 手冊 |

| 14:45–14:50 | 實作回顧與問答 | Q&A | 記錄常見問題，供第 6 堂參考 |

講師提醒：
- 這是最容易出狀況的段落，準備好以下備案：
  - 預錄的 Demo 影片
  - 備用 API Key
  - 助教協助排除個別學員的技術問題
- 預留 5 分鐘的緩衝時間

### 第 6 堂：教材製作與教學輔導強化工作坊（15:00–16:00）

核心目標：把 Agent 放進博幼幕僚工作流，做出可重複使用的原型與 SOP

| 時間 | 內容 | 型態 | 注意事項 |
|------|------|------|----------|
| 15:00–15:05 | 任務重新定位 | 講授 | 先說清楚今天看的是流程是否可用，別把重點放在工具效果上 |
| 15:05–15:13 | 去識別化微演練 | 實作 | 先處理敏感資料，再開始用 Agent |
| 15:13–15:20 | 任務選擇與需求拆解 | 討論 | 請每組先寫出輸入、輸出、限制與人工審查點 |
| 15:20–15:38 | Agent 原型實作 | 實作 | 講師與助教巡場，避免學員一次塞太多要求 |
| 15:38–15:48 | Rubric 交叉審查 | 討論 | 另一組檢查正確性、適配性、隱私與可追蹤性 |
| 15:48–15:56 | SOP 收斂 | 實作 | 每組至少整理出任務名稱、輸入資料、Agent 動作、人工審查點 |
| 15:56–16:00 | 帶走承諾與收尾 | 講授 | 請每組寫下兩週內要試行的一件小事 |

場景選項（以博幼基金會幕僚工作為主）：
1. 教學輔導異常雷達：整理各中心回報，標記需優先支援的單元與協作事項
2. 教材修訂任務追蹤：把會議紀錄整理成待修項、負責人、期限與驗收標準
3. 學習支持需求分類：將家長、老師或社工回饋分流成可處理的需求表
4. 跨中心教材落差分析：比較同一單元在不同中心的卡關點與補救方向
5. 教材製作 Agent 工作流：先做差異化練習、教師提示語與補救教學建議第一版

### 第 6 堂講師提醒

- **先守住節奏**：如果現場卡住，不要急著救 prompt，先回頭檢查任務定義與輸出欄位。
- **先保住三個成果**：去識別化、第一版原型、SOP。只要這三個有留下，這堂課就算站得住。
- **不要讓學員把個案決定交給 Agent**：凡是涉及學童支持、家庭處境或正式教材定稿，一律提醒要人工覆核。
- **巡場時優先問這兩句**：
  - 你這一版要交給誰看？
  - 這份輸出裡哪一段一定要人來判斷？

## 四、Demo 操作手冊

### Demo 1：不同模型執行同一任務（第 2 堂）

目的：讓學員直觀感受不同模型的差異

準備：
- 確認三個 API Key 均可用
- 預先測試所有提示詞，確認回應時間和品質

操作步驟：

1. 開啟三個瀏覽器分頁：ChatGPT、Claude、Gemini

2. 任務一：摘要能力（5 分鐘）
   - 輸入提示詞：「請用 100 字以內摘要以下文章：[預先準備的一篇 500 字中文新聞]」
   - 同時貼上三個平台，觀察回應速度和品質差異
   - 討論重點：摘要品質、風格差異、回應速度

3. 任務二：推理能力（5 分鐘）
   - 輸入提示詞：「一個房間裡有 3 個開關控制隔壁房間的 3 盞燈。你只能去隔壁房間一次。如何確定每個開關對應哪盞燈？」
   - 同時貼上三個平台
   - 討論重點：推理邏輯的正確性、解釋的清晰度

4. 任務三：中文能力（5 分鐘）
   - 輸入提示詞：「請將以下英文教育報告摘要翻譯為適合台灣讀者閱讀的中文，保留專業術語的原文：[預先準備一篇關於偏鄉教育或課後輔導的英文段落]」
   - 同時貼上三個平台
   - 討論重點：翻譯的自然度、專業術語處理方式、教育領域用語的適當性

注意事項：
- 如果某平台回應過慢，跳過該平台，不要讓學員等待
- 預先準備好的回應截圖作為備案
- 強調「沒有最好的模型，只有最適合的模型」

### Demo 2：Hermes Agent 操作（第 5 堂）

目的：讓學員完成第一個 Agent 實作

操作步驟：

1. 安裝示範（5 分鐘）
   ```bash
   # 展示安裝指令
   curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

   # 驗證安裝
   hermes --version

   # 設定 API Key
   export OPENAI_API_KEY="sk-..."
   ```
   - 講師先示範一次，然後讓學員跟著操作

2. 第一次對話（5 分鐘）
   ```bash
   hermes chat
   ```
   - 輸入：「你好，請介紹你自己」
   - 輸入：「博幼基金會在台灣有幾個課輔中心？服務對象是誰？」（觀察 Agent 是否能回答關於博幼的問題）
   - 討論：Agent 和 ChatGPT 的回應有什麼不同？

3. 啟用工具（10 分鐘）
   - 展示如何在設定中啟用工具（如網頁搜尋、檔案讀寫）
   - 重試天氣問題，觀察 Agent 使用工具後的回應差異
   - 請 Agent 讀取一個 CSV 檔案並回答問題

4. 觀察自學習迴圈（5 分鐘）
   - 請 Agent 執行一個任務（如「整理這段文字的要點」）
   - 再次執行類似任務
   - 展示 Agent 的記憶或技能累積記錄

注意事項：
- 終端機字體務必放大，確保後排學員可閱讀
- 每個步驟都暫停讓學員跟上
- 遇到錯誤時不要慌張，當作「除錯教學」的機會

## 五、常見技術問題排解

### 安裝問題

| 問題 | 可能原因 | 解法 |
|------|----------|------|
| `command not found: hermes` | 安裝路徑未加入 PATH | 重新開啟終端機，或執行 `source ~/.bashrc` / `source ~/.zshrc` |
| `python3: command not found` | Python 未安裝或未加入 PATH | 安裝 Python 3.11+，確認 PATH 設定 |
| 安裝腳本報錯 `Permission denied` | 沒有執行權限 | `chmod +x install.sh` 後再執行 |
| macOS 提示「無法驗證開發者」 | Gatekeeper 安全限制 | 系統偏好設定 > 安全性 > 允許執行 |

### API 問題

| 問題 | 可能原因 | 解法 |
|------|----------|------|
| `Authentication Error` | API Key 錯誤或未設定 | 確認環境變數是否正確設定：`echo $OPENAI_API_KEY` |
| `Rate Limit Exceeded` | 短時間內請求過多 | 等待 1–2 分鐘後重試 |
| `Insufficient Quota` | 帳戶餘額不足 | 儲值或使用備用 API Key |
| `Model Not Found` | 模型名稱錯誤 | 確認使用的模型名稱是否正確 |

### 連線問題

| 問題 | 可能原因 | 解法 |
|------|----------|------|
| 請求超時 | 網路不穩定或 VPN 干擾 | 嘗試關閉 VPN、切換 Wi-Fi 或使用手機熱點 |
| SSL 錯誤 | 公司防火牆攔截 | 改用個人裝置或手機熱點 |
| 下載緩慢 | 頻寬不足 | 課前預先安裝，避免課堂上等待 |

### Hermes Agent 操作問題

| 問題 | 可能原因 | 解法 |
|------|----------|------|
| Agent 回應空白 | 模型 API 未正確設定 | 檢查 API Key 設定 |
| 工具未被使用 | 工具未啟用或模型不支援 Tool Use | 確認設定檔中工具已啟用，確認使用的模型支援 Tool Use |
| Agent 回應非預期 | 提示詞不夠明確 | 嘗試更具體的指示 |
| 記憶未保留 | 記憶功能未啟用 | 檢查記憶設定 |

## 六、評量建議

### 課堂參與與討論（30%）

評量方式：
- 討論環節的參與度（是否主動發言、提出有深度的問題）
- 對三層架構的理解（能否用自己的話解釋）
- 課堂問答的回應品質

評分標準：
- 優秀（27–30）：積極參與討論，能清晰表達見解，主動協助其他學員
- 良好（24–26）：參與多數討論，表達清楚，展現理解
- 及格（18–23）：有基本參與，理解核心概念
- 待加強（<18）：參與度低，概念理解不足

### 第 5 堂 Hands-on 實作完成度（30%）

評量方式：
- 檢查學員的終端機畫面或操作截圖

評分標準：
- 優秀（27–30）：完成所有實作任務，能清楚解釋每個步驟的意義
- 良好（24–26）：完成主要實作任務，對操作有基本理解
- 及格（18–23）：完成基本安裝和第一次對話
- 待加強（<18）：未能完成安裝，需要大量協助

### 第 6 堂工作坊分組成果發表（40%）

評量方式：
- 各組 3–5 分鐘的成果展示
- 包含：場景描述、Agent 設計、實作過程、成果展示

評分標準：
- 優秀（36–40）：場景貼合實際需求，Agent 設計合理，實作完整，展示清晰
- 良好（32–35）：場景合理，Agent 設計基本可行，有實際操作成果
- 及格（24–31）：有場景構想和基本實作嘗試
- 待加強（<24）：場景模糊，實作未完成

### 評量注意事項

- 本課程定位為「入門」，評量重點在理解和參與，而非技術完美
- 鼓勵學員分享實作過程中的失敗經驗，而非只展示成功
- 工作坊評量以小組為單位，但注意每位成員的參與程度
