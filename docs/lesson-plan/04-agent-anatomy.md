# 第 4 堂：Agent 解剖學

## 基本資訊

- **時長**：50 分鐘
- **型態**：講授 + 互動討論 + 即時 Demo
- **對應學習目標**：4.1 理解 Agent 四大組成要素、4.2 比較工具系統設計風格、4.3 理解記憶與安全機制、4.4 辨識 Agent 常見反模式

---

## 教學流程

### 第一階段：開場與概念導入（5 min）

**講授要點**

- 回顧前三堂建立的基礎：我們已經知道 Model 是大腦、Harness 是管理員
- 今天要把 Agent 完整拆解
- 公式揭示：**Agent = Model + Harness + Tools + Memory**
- 用人體做比喻：
  - Model = 大腦（思考與推理）
  - Harness = 神經系統與自律神經（協調、控制、保護）
  - Tools = 雙手與工具箱（實際執行動作）
  - Memory = 海馬迴與長期記憶（累積經驗）

**互動活動**

- 問學員：「如果一個人只有大腦但沒有雙手，能完成工作嗎？」引導到 Tools 的重要性
- 追問：「如果一個人很聰明但每次見面都忘記你是誰？」引導到 Memory 的必要性

---

### 第二階段：Agent 四大組成拆解（10 min）

**講授要點**

1. **Model（模型）**
   - 負責理解輸入、推理規劃、產生輸出
   - 可以是 Claude、GPT、開源模型等
   - 重點：Model 本身「只會說話」，不會做事

2. **Harness（控管框架）**
   - 管理對話狀態（目前進行到哪一步）
   - 約束工具使用範圍（哪些工具可以用、怎麼用）
   - 權限控制（能不能刪檔案、能不能連外網）
   - 錯誤處理（工具失敗時怎麼辦）
   - 資源與預算追蹤（已經花了多少 token、跑了幾輪）

3. **Tools（工具）**
   - 讓 Agent 從「只會說話」變成「能做事」
   - 範例工具：網頁搜尋、檔案讀寫、發送訊息、執行程式碼、呼叫 API
   - 博幼場景範例：讀取課輔進度檔案、寫入週報、搜尋教學資源、發送家長通知
   - 工具的定義包含：名稱、描述、輸入參數、輸出格式

4. **Memory（記憶）**
   - 短期記憶：當前對話的上下文歷史
   - 長期記憶：跨對話累積的知識與技能
   - 狀態記憶：跨平台的執行狀態（例如 Telegram 上開始的工作，在 CLI 上繼續）

**板書 / 投影片建議**

畫出四象限圖，中心是 Agent，四個角分別標示 Model、Harness、Tools、Memory，並用箭頭標示彼此關係。

### 第三階段：工具系統深探 — 兩種設計風格（10 min）

**講授要點**

工具系統是 Agent 能力的核心差異化來源。業界有兩種主流設計風格：

**風格一：型別安全介面（Typed Interface）**

- 代表：Claude Code 的工具系統
- 特點：每個工具有嚴格的型別定義（TypeScript/JSON Schema），參數型別、必填/選填、回傳格式都事先定好
- 優點：
  - 編譯期就能抓到錯誤，不會傳錯參數型別
  - IDE 有自動補全和提示
  - 較不容易因為格式問題導致工具呼叫失敗
- 缺點：
  - 新增工具需要寫型別定義，門檻較高
  - 彈性較低，臨時調整不便
- 適合：正式產品環境、團隊協作、需要穩定可靠

**風格二：彈性註冊模式（Registry Pattern）**

- 代表：Hermes Agent 的工具系統
- 特點：用裝飾器或註冊函式把工具「掛上去」，參數用自然語言描述即可
- 優點：
  - 快速上手，幾行程式碼就能加新工具
  - 彈性高，容易實驗和迭代
  - 適合原型開發
- 缺點：
  - 型別錯誤要等到執行期才會發現
  - 大量工具時缺乏自動驗證
- 適合：快速開發、個人專案、原型驗證

**Demo 步驟**

展示兩種風格的程式碼對照（投影）：

```
# 風格二（彈性註冊 — Hermes 風格）
@tool("read_progress", "讀取學童課輔進度檔案")
def read_progress(student_id: str, subject: str = "all"):
    ...
```

```
// 風格一（型別安全 — Claude Code 風格）
const readProgressTool = tool({
  name: "read_progress",
  description: "讀取學童課輔進度檔案",
  parameters: z.object({
    student_id: z.string().describe("學童編號"),
    subject: z.string().default("all").describe("科目，預設全部"),
  }),
  execute: async ({ student_id, subject }) => { ... }
});
```

**互動活動**

- 問學員：「如果你要幫博幼基金會建一個課輔行政 Agent，會選哪種風格？為什麼？」
- 引導討論：考慮因素包括團隊技術能力、維護需求、上線時程

### 第四階段：記憶機制與安全性（10 min）

**講授要點 — 記憶機制**

1. **對話歷史（Conversation History）**
   - 最基本的記憶形式
   - 保留完整的使用者與 Agent 對話紀錄
   - 限制：上下文視窗有長度上限，太長會被截斷或摘要化

2. **技能累積（Skill Accumulation）**
   - Hermes 的特色：Agent 會從成功經驗中「學到技能」
   - 例如：第一次花 5 步完成某任務，下次遇到類似任務可以 1 步搞定
   - 這不是模型微調，而是把成功的「工作流程」存下來重複使用

3. **跨平台狀態（Cross-Platform State）**
   - 在 Telegram 上開始的對話，可以在 CLI 上接續
   - 需要統一的狀態儲存層
   - Hermes 的架構原生支援這點

**講授要點 — 安全性**

Agent 安全性比一般軟體更需要注意，因為 Agent 會「自己決定要執行什麼動作」。

1. **沙箱隔離（Sandboxing）**
   - Agent 執行的程式碼在隔離環境中運行
   - Hermes 支援 Docker 容器沙箱、SSH 遠端沙箱、Modal 雲端沙箱
   - 即使 Agent 被誘導執行惡意指令，也不會影響宿主機

2. **權限審核（Permission Review）**
   - 工具依危險等級分層
   - 高風險操作（刪檔案、發送訊息）需要使用者確認
   - 低風險操作（讀取檔案、搜尋）可自動放行

3. **迭代預算控制（Iteration Budget）**
   - 設定 Agent 最多可以跑幾輪（例如 Hermes 的 IterationBudget）
   - 防止無窮迴圈消耗資源
   - 也防止 token 費用失控

**比喻**

- 沙箱 = 讓小孩在遊戲圍欄裡玩，不會跑到馬路上
- 權限審核 = 金融交易的雙重確認
- 預算控制 = 給小孩零用錢，花完就停

**博幼基金會特有安全考量**

以博幼基金會的場景為例，Agent 在處理課輔業務時，必須特別注意以下安全議題：

1. **學童個資保護**
   - 學童姓名、出生日期、家庭狀況都屬於敏感個資
   - Agent 處理學童資料時，必須限制只能「讀取」和「彙整」，不能對外傳輸
   - 產出的報表需自動遮蔽可直接識別個人的欄位（如用編號取代姓名）

2. **社工個案保密**
   - 社工輔導紀錄涉及家訪筆記、家庭狀況評估等高度敏感資訊
   - 不同社工之間的個案資料應有存取隔離
   - Agent 處理個案相關任務時，需特別標記資料機密等級，禁止跨中心彙整時洩露個案內容

3. **跨中心資料彙整風險**
   - 博幼全台 17 處課輔中心的資料格式可能不一致
   - Agent 在彙整跨中心資料時，需確保不會把 A 中心的學童資料混入 B 中心的報表中

### 第五階段：反模式 — Agent 常見失敗模式（10 min）

**講授要點**

知道什麼會出錯，跟知道怎麼做對一樣有用。

**反模式 1：無窮迴圈（Infinite Loop）**

- 現象：Agent 不斷重複同樣的操作，永遠不會停止
- 原因：缺少終止條件，或錯誤處理不當導致 Agent 以為「再試一次就會成功」
- 解法：設定 IterationBudget（迭代上限）、加入進度偵測（連續 N 次相同結果就中止）

**反模式 2：工具濫用（Tool Abuse）**

- 現象：Agent 用錯工具，或過度頻繁呼叫工具
- 原因：工具描述不清楚，Agent 誤解工具用途
- 解法：精確的工具描述、設定呼叫頻率上限、Harness 層加入工具選擇審核

**反模式 3：上下文爆炸（Context Explosion）**

- 現象：對話歷史越來越長，最後塞爆上下文視窗，Agent 開始「失憶」或胡言亂語
- 原因：沒有做上下文管理，把所有對話內容都塞進去
- 解法：定期摘要化歷史、只保留關鍵資訊、設定上下文長度上限

**反模式 4：權限失控（Permission Escalation）**

- 現象：Agent 取得了超出預期的權限，造成安全風險
- 原因：為了方便，把所有工具都設為「自動允許」
- 解法：最小權限原則、高風險操作一律需人工確認、定期審計 Agent 操作日誌

**互動活動**

- 給學員一個情境：「你的 Agent 在幫你彙整課輔班學童出勤記錄時，突然開始不斷刪除檔案又重建，持續了 10 分鐘還沒停。」
- 問學員：「這是哪個反模式？你會怎麼處理？」
- 正確答案：無窮迴圈 + 工具濫用；處理方式是立即手動停止、檢查迭代預算設定、確認工具描述是否清晰

### 第六階段：總結與預告（5 min）

**總結重點**

1. Agent 的四個組成：Model、Harness、Tools、Memory，缺一不可
2. 工具系統有型別安全和彈性註冊兩種風格，各有適用場景
3. 記憶不只是對話歷史，還包括技能累積和跨平台狀態
4. 安全三道防線：沙箱、權限、預算
5. 四個反模式：無窮迴圈、工具濫用、上下文爆炸、權限失控

**預告下一堂**

- 下一堂（第 5 堂）是實作課，會實際安裝並操作 Hermes Agent，體驗 Model + Harness + Tools + Memory 如何在真實框架中運作
- 請學員確認自己的筆電環境：
  - 需要有終端機（macOS 用 Terminal，Windows 用 PowerShell 或 WSL）
  - 需要有穩定的網路連線
  - 如果公司筆電有安裝限制，請提前聯繫講師

## 關鍵概念

| 概念 | 一句話解釋 |
|------|-----------|
| Agent 四要素 | Model（大腦）+ Harness（管理）+ Tools（雙手）+ Memory（記憶） |
| 型別安全工具 | 先定義嚴格的參數型別，再使用；適合正式環境 |
| 彈性註冊工具 | 用描述語句快速掛載工具，彈性高；適合快速開發 |
| 對話歷史 | Agent 的短期記憶，保存當前對話的所有訊息 |
| 技能累積 | Agent 從成功經驗中學習，下次更快完成類似任務 |
| 沙箱隔離 | 在安全容器中執行 Agent 操作，不影響主系統 |
| 迭代預算 | 限制 Agent 最多執行幾輪，防止無窮迴圈 |
| 上下文爆炸 | 對話歷史過長導致 Agent 失去焦點或產生錯誤 |

## 教學提示

1. **學員可能對「Harness」感到陌生**：這個詞在中文裡沒有很好的對應翻譯。建議用「控管框架」或「管理員」來解釋，強調它的角色是「管束 Agent 行為的那一層」。

2. **型別安全 vs. 彈性註冊的比較容易流於技術細節**：不需要讓學員記住程式碼語法，重點是讓他們理解「嚴謹但費工」vs.「靈活但風險較高」的取捨。可以用「開車上路要有駕照 vs. 騎腳踏車不用」來比喻。

3. **反模式單元是亮點**：學員通常對「什麼會出錯」比「什麼是正確的」更有共鳴。多花時間在情境討論上，讓學員自己判斷是哪個反模式。

4. **安全性部分不要太技術化**：不需要講 Docker 的技術細節，用「隔離的房間」來解釋即可。重點是讓學員理解「為什麼 Agent 需要被管束」。

5. **時間控制**：第三階段（工具系統）和第五階段（反模式）是重點，各留 10 分鐘。如果時間不夠，可以壓縮第四階段的記憶部分。

## 延伸活動（若有餘裕時間）

### 活動：Agent 故障診斷站

給學員 4 張「故障卡片」，每張描述一個 Agent 異常行為情境。學員分組討論，判斷是哪個反模式，並提出修復建議。

**故障卡片範例：**

- 卡片 A：Agent 在整理家長來信時，把同一封信讀了 50 次，每次都說「讓我重新檢查一下」。（無窮迴圈）
- 卡片 B：Agent 的對話紀錄已經累積了 10 萬字，開始把「陳老師」叫成「陳家長」。（上下文爆炸）
- 卡片 C：為了方便測試，所有工具都設成自動同意，結果 Agent 把學童個資寄給了不相關的外部單位。（權限失控）
- 卡片 D：Agent 用「搜尋網頁」工具來讀取本地課輔進度檔案，每次都失敗但繼續嘗試。（工具濫用）
