# 第 4 堂：Agent 解剖學

## 基本資訊

- **時長**：50 分鐘
- **型態**：講授 + 互動討論 + 即時 Demo
- **對應學習目標**：4.1 理解 Agent 四大組成要素、4.2 認識工具的能力光譜與風險分級、4.3 理解 Context Awareness 對 Agent 表現的影響、4.4 辨識 Agent 常見問題並掌握使用者的應對策略

---

## 教學流程

### 第一階段：開場與概念導入（5 min）

**學習重點**

- 回顧前三堂建立的基礎：我們已經知道 Model 是大腦、Harness 是管理員
- 今天要把 Agent 完整拆解
- 公式揭示：**Agent = Model + Harness + Tools + Memory**
- 用人體做比喻：
  - Model = 大腦（思考與推理）
  - Harness = 神經系統與自律神經（協調、控制、保護）
  - Tools = 雙手與工具箱（實際執行動作）
  - Memory = 海馬迴與長期記憶（累積經驗）

**練習與討論**

- 想想看：「如果一個人只有大腦但沒有雙手，能完成工作嗎？」這就是 Tools 的重要性
- 再想想：「如果一個人很聰明但每次見面都忘記你是誰？」這就是 Memory 的必要性

---

### 第二階段：Agent 四大組成拆解（10 min）

**學習重點**

1. **Model（模型）**
   - 負責理解輸入、推理規劃、產生輸出
   - 可以是 Claude、GPT、開源模型等
   - 重點：Model 本身「只會說話」，不會做事

2. **Harness（控管框架）**
   - 管理對話狀態（目前進行到哪一步）
   - 約束工具使用範圍（哪些工具可以用、怎麼用）
   - 權限控制（能不能刪檔案、能不能連外網）
   - 錯誤處理（工具失敗時怎麼辦）
   - 資源與預算追蹤（已經花了多少 token、跑了幾輪）

3. **Tools（工具）**
   - 讓 Agent 從「只會說話」變成「能做事」
   - 範例工具：網頁搜尋、檔案讀寫、發送訊息、執行程式碼、呼叫 API
   - 博幼場景範例：讀取課輔進度檔案、寫入週報、搜尋教學資源、發送家長通知
   - 工具的定義包含：名稱、描述、輸入參數、輸出格式

4. **Memory（記憶）**
   - 短期記憶：當前對話的上下文歷史
   - 長期記憶：跨對話累積的知識與技能
   - 狀態記憶：跨平台的執行狀態（例如 Telegram 上開始的工作，在 CLI 上繼續）

### 第三階段：工具能力與風險 — 使用者視角（10 min）

**學習重點**

工具是 Agent 從「只能說話」變成「能做事」的關鍵。作為使用者，你需要理解工具的能力範圍和風險等級，才能判斷一個 Agent 是否安全、是否適合你的任務。

#### 工具的能力光譜

Agent 的工具可以按風險從低到高排列成一個光譜：

```
低風險 ◄──────────────────────────────────────────► 高風險

 讀取型      查詢型       寫入型        外部通訊型
 （看資料）  （找資料）   （改資料）     （傳出去）
```

| 風險等級 | 類型 | 代表工具 | 你該注意什麼 |
|----------|------|---------|-------------|
| **低** | 讀取型 | 讀檔案、讀行事曆、查看資料庫 | 只看不改，風險最低；但仍需注意是否會讀到敏感資料 |
| **中** | 查詢型 | 網頁搜尋、API 查詢、資料庫搜尋 | 查詢內容可能含有機密資訊，確認查詢不會外洩 |
| **高** | 寫入型 | 寫檔案、修改資料庫、更新行事曆 | Agent 可以改變你的資料，必須有確認機制 |
| **最高** | 外部通訊型 | 發 Email、傳訊息、呼叫外部 API | 資料一旦送出就無法收回，必須雙重確認 |

#### 博幼場景的風險對應

以博幼基金會的日常工作為例：

| 場景 | 用到的工具 | 風險等級 | 安全考量 |
|------|-----------|----------|---------|
| 彙整課輔週報 | 讀取進度檔案 → 寫入彙整報告 | 低 → 高 | 彙整結果不能包含可直接識別的學童個資 |
| 搜尋教學資源 | 網頁搜尋 → 整理摘要 | 中 | 搜尋內容不涉及學童資訊，相對安全 |
| 發送家長通知 | 讀取通知範本 → 發送 Email | 低 → 最高 | 發送前必須確認收件人和內容，尤其不能群發時暴露其他家長的 Email |
| 整理個案記錄 | 讀取輔導紀錄 → 寫入摘要報告 | 低 → 高 | 個案內容高度敏感，建議只用「摘要」方式處理 |

#### 作為使用者的判斷指標

當你評估一個 Agent 時，關注它的工具設計：

1. **工具是否分級管理？** 好的 Agent 會把高風險工具設為「需確認」，低風險工具才能自動執行
2. **你能看到 Agent 使用了哪些工具嗎？** 透明的 Agent 會顯示每一步用了什麼工具
3. **工具範圍是否合理？** 一個「課輔行政 Agent」不需要有「刪除資料庫」的能力
4. **有沒有敏感資料的防護？** 處理個資時，是否有自動遮蔽或警告機制

**練習與討論**

- 想想看：「一個 Agent 宣稱能幫你處理所有行政工作，但它的工具清單包含『讀取所有檔案』『發送 Email』『執行系統指令』，你會怎麼評估？」
- 討論方向：工具越多不一定越好，重點是範圍是否合理、是否有分級管控

### 第四階段：Context Awareness — Agent 的理解力關鍵（10 min）

**學習重點**

Context（上下文）是 Agent 能否正確理解任務、做出準確判斷的核心。上一堂課我們學到了 Context 的三個組成部分，今天要深入看 Context 如何影響 Agent 的表現，以及你作為使用者可以怎麼管理它。

#### Agent 如何理解你的需求

Agent 所「看到」的資訊，由三個部分組成（複習）：

```
┌──────────────────────────────────────────────┐
│            Agent 看到的 Context               │
│                                              │
│  ① 系統提示（System Prompt）                  │
│     「你是課輔行政助理，擅長整理報告...」       │
│     → 設定角色、行為規範、能力範圍              │
│                                              │
│  ② 對話歷史（Conversation History）           │
│     你：「幫我彙整本週課輔進度」                │
│     Agent：「好的，我需要先讀取...」            │
│     → 提供任務脈絡和對話邏輯                   │
│                                              │
│  ③ 工具執行結果（Tool Results）               │
│     [檔案內容：埔里中心週報...]                 │
│     [搜尋結果：偏鄉教育政策...]                 │
│     → 補充事實資料和操作結果                    │
│                                              │
│  這三者共享 Context Window 的總容量            │
└──────────────────────────────────────────────┘
```

#### Context Window 的實際影響

Context Window 就像 Agent 的「短期記憶工作空間」，空間有限，塞滿了就得「忘掉」舊的東西。

**對話長度的影響：**

| 對話狀態 | Agent 表現 | 你會觀察到 |
|----------|-----------|-----------|
| 短對話（剛開始） | 精準、聚焦 | 正確理解任務，步驟精簡 |
| 中等對話（5-8 輪） | 仍然可靠 | 可能開始省略一些細節 |
| 長對話（15+ 輪） | 開始「失焦」 | 忘記早期的指示、重複之前做過的事 |
| 超長對話（30+ 輪） | 明顯退化 | 自相矛盾、答非所問、遺漏關鍵限制 |

**工具結果的影響：**

- 工具回傳大量資料時（例如讀取一個 5,000 字的檔案），這些內容會佔用 Context 空間
- 連續讀取多個大檔案後，Agent 可能「忘記」你最開始的指示
- 這就是為什麼複雜任務有時候「中途重來」反而比「繼續硬撐」效果好

#### 使用者的 Context 管理策略

這是最實用的部分——你不需要理解技術細節，但你需要知道怎麼跟 Agent 有效溝通。

**策略一：一次把需求說清楚**

```
❌ 模糊版：
「幫我整理這些資料」

✅ 精準版：
「請讀取 ~/workshop/notes.txt，整理成一份課輔中心工作摘要：
 1. 按重要性排序
 2. 標記需要後續跟進的事項（附截止日期）
 3. 輸出為 Markdown 格式
 4. 存到 ~/workshop/summary.md
 注意：不要包含學童真實姓名，用編號代替」
```

為什麼精準版更好？因為它一次提供了：任務目標、具體步驟、輸出格式、儲存位置、限制條件。Agent 不需要「猜」你要什麼。

**策略二：知道何時開新對話**

| 情境 | 建議 | 原因 |
|------|------|------|
| 任務完全切換 | 開新對話 | 舊的 Context 會干擾新任務 |
| Agent 開始「失焦」 | 開新對話 | Context 可能已經太長 |
| 同一任務的後續步驟 | 繼續對話 | 需要前面的 Context |
| Agent 回答偏離指示 | 先嘗試重述，不行就開新對話 | 可能是 Context 中有矛盾資訊 |

**策略三：辨識 Agent「理解錯誤」的信號**

Agent 不會告訴你「我搞錯了」，但它會透過行為透露蛛絲馬跡：

- **答非所問**：你問 A，它回答 B → 可能是 Context 中有更強烈的暗示讓它偏離
- **重複之前的內容**：把前面已經處理過的東西又拿出來 → Context 太長，忘記做過了
- **遺漏關鍵限制**：你說了「不要包含姓名」但它還是放了 → 限制被長對話的後續內容「淹沒」了
- **格式不一致**：前面輸出 Markdown，後面突然變成純文字 → Context 切換時遺失了格式指示

#### 記憶機制補充

除了即時的 Context，Agent 還有其他形式的「記憶」：

1. **對話歷史（短期）**：即 Context Window 內的內容，對話結束就消失
2. **技能累積（長期）**：部分 Agent（如 Hermes）會從成功經驗中學到「技能模板」，下次遇到類似任務可以更快完成
3. **跨平台狀態**：在 Telegram 上開始的對話，可以在 CLI 上接續

---

#### 安全性與博幼特有考量

Agent 安全性比一般軟體更需要注意，因為 Agent 會「自己決定要執行什麼動作」。三道基本防線：

1. **沙箱隔離**：Agent 在隔離環境中運行，即使出錯也不會影響你的電腦
2. **權限審核**：高風險操作需要你確認才能執行
3. **迭代預算控制**：限制 Agent 最多可以跑幾輪，防止無窮迴圈

**博幼基金會的特別安全考量：**

1. **學童個資保護**：學童姓名、出生日期、家庭狀況都屬於敏感個資。Agent 處理學童資料時，必須限制只能「讀取」和「彙整」，不能對外傳輸。產出的報表需自動遮蔽可直接識別個人的欄位
2. **社工個案保密**：社工輔導紀錄涉及高度敏感資訊，不同社工之間的個案資料應有存取隔離
3. **跨中心資料彙整風險**：博幼全台 17 處課輔中心的資料格式可能不一致，Agent 在彙整時需確保不會把 A 中心的學童資料混入 B 中心的報表中

### 第五階段：常見問題 — 使用者的應對指南（10 min）

**學習重點**

知道 Agent 會出現什麼問題，跟知道它能做什麼一樣重要。以下四個是使用 Agent 時最常遇到的問題，以及你作為使用者可以怎麼應對。

**問題一：無窮迴圈 — Agent 停不下來**

- **你會看到什麼**：Agent 不斷重複同樣的操作，例如「讓我再檢查一次」「讓我重新嘗試」，持續很久都不結束
- **原因**：Agent 的錯誤處理機制不夠好，遇到錯誤時以為「再試一次就會成功」
- **你該怎麼做**：
  - 立刻停止 Agent（中斷執行）
  - 開新對話，重新下達指令，這次加入更多限制條件
  - 如果反覆發生，換個方式描述任務，或把任務拆成更小的步驟

**問題二：工具濫用 — Agent 用錯工具**

- **你會看到什麼**：Agent 用「搜尋網頁」來找本地檔案、用「寫入」來做「讀取」、或者頻繁呼叫同一個工具卻得不到結果
- **原因**：任務描述不夠清楚，Agent 誤解了你的意思
- **你該怎麼做**：
  - 重新描述任務，明確說明要用什麼方式完成
  - 範例：「請用讀取檔案的方式（不要用搜尋）打開 ~/workshop/data.txt」
  - 如果 Agent 持續選錯工具，開新對話用更精確的描述重新開始

**問題三：上下文爆炸 — Agent 失去焦點**

- **你會看到什麼**：Agent 開始遺忘你早期的指示、重複之前說過的話、答非所問、自相矛盾
- **原因**：對話太長，Context Window 已經被塞滿，Agent 無法同時記住所有資訊
- **你該怎麼做**：
  - **開新對話**：這是最直接有效的解法
  - 在新對話中，用一段話總結之前的進展，然後繼續
  - 範例：「之前你已經幫我整理了埔里和竹東的週報，現在請繼續整理新埔的」
  - 預防：複雜任務拆成多次對話，每次處理一個部分

**問題四：權限失控 — Agent 做了不該做的事**

- **你會看到什麼**：Agent 在你沒預期的情況下刪除檔案、發送訊息、存取敏感資料
- **原因**：Agent 的工具權限設定過於寬鬆，高風險操作沒有確認機制
- **你該怎麼做**：
  - 事前：確認 Agent 的工具權限設定，高風險工具務必開啟確認
  - 事中：看到 Agent 要執行高風險操作時，仔細確認再放行
  - 事後：如果已經發生，記錄下來並調整權限設定，避免再次發生

**問題對照速查表：**

| 你觀察到的現象 | 可能的問題 | 第一步行動 |
|--------------|-----------|-----------|
| Agent 重複同一動作不停 | 無窮迴圈 | 立刻中斷 |
| Agent 選了不對的工具 | 工具濫用 | 重新描述任務 |
| Agent 忘記了你的指示 | 上下文爆炸 | 開新對話 |
| Agent 做了你沒授權的事 | 權限失控 | 檢查權限設定 |

**練習與討論**

- 情境題：「你的 Agent 在幫你彙整課輔班學童出勤記錄時，突然開始不斷重複讀取同一個檔案，每次都說『讓我再確認一下』，已經持續 10 分鐘。」
- 想想看：「這是哪個問題？你會怎麼處理？」
- 提示方向：判斷問題類型 → 採取對應的第一步行動 → 思考如何避免下次再發生

### 第六階段：總結與預告（5 min）

**總結重點**

1. Agent 的四個組成：Model、Harness、Tools、Memory，缺一不可
2. 工具有風險光譜：讀取（低）→ 查詢（中）→ 寫入（高）→ 外部通訊（最高）
3. Context Awareness 是 Agent 正確理解任務的關鍵，影響所有表現
4. 使用者可以透過精準提問、適時開新對話、辨識失焦信號來管理 Context
5. 四個常見問題：無窮迴圈、工具濫用、上下文爆炸、權限失控——每個都有對應的使用者應對策略

**預告下一堂**

- 下一堂（第 5 堂）是實作課，會實際操作 Hermes Agent，體驗今天學到的概念如何在真實 Agent 中運作——特別是 Context Awareness 的實際體驗
- 請確認你的筆電環境：
  - 需要有終端機（macOS 用 Terminal，Windows 用 PowerShell 或 WSL）
  - 需要有穩定的網路連線
  - 如果公司筆電有安裝限制，請提前聯繫課務人員

## 關鍵概念

| 概念 | 一句話解釋 |
|------|-----------|
| Agent 四要素 | Model（大腦）+ Harness（管理）+ Tools（雙手）+ Memory（記憶） |
| 工具風險光譜 | 讀取型（低）→ 查詢型（中）→ 寫入型（高）→ 外部通訊型（最高） |
| Context Awareness | Agent 透過上下文理解任務的能力，直接影響表現品質 |
| Context Window | Agent 的「工作桌面」，空間有限，放太多會掉東西 |
| 精準提問 | 一次說清楚任務目標、步驟、格式、限制，讓 Agent 不需要猜 |
| 開新對話時機 | 任務切換、Agent 失焦、回答偏離時，開新對話比重來好 |
| 上下文爆炸 | 對話歷史過長導致 Agent 失去焦點或產生錯誤 |
| 安全三防線 | 沙箱隔離、權限審核、迭代預算控制 |
