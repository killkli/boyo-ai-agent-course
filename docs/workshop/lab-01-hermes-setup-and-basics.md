# Lab 1：Hermes 安裝與基礎操作

## 基本資訊

- **單元名稱**：Lab 1：Hermes 安裝與基礎操作
- **適用課程**：Hermes Agent 全天實作工作坊
- **時長**：45 分鐘
- **型態**：Hands-on 實作
- **對應課表**：09:25–10:10
- **對應學習目標**：完成 Hermes 安裝與設定、執行第一個 Agent 任務、理解基本操作節奏

## 單元目標

完成本 Lab 後，學員應能：

1. 在自己的電腦上完成 Hermes 安裝與初始設定。
2. 使用 `hermes` 指令確認版本與設定是否正常。
3. 進入互動模式，向 Hermes 下達第一個整理任務。
4. 看懂一次基本的 Agent 操作流程：接收任務、讀取資料、整理內容、寫出結果。

## 課前準備

### 講師準備

- 確認教室網路穩定，並準備手機熱點作為備援。
- 預先在講師電腦完成 Hermes 安裝與 `hermes setup` 設定。
- 準備 2–3 組備用 API Key，供現場無法即時申請的學員使用。
- 準備一份可直接貼上的測試文字內容，避免學員臨時找不到素材。
- 如果現場裝機風險較高，先錄好 3–5 分鐘的安裝 Demo 影片。
- 提前確認學員使用的作業系統比例，特別留意 Windows 學員是否熟悉 PowerShell 或 WSL。

### 學員準備

- 自備筆電並確認可連網。
- 可開啟終端機：macOS 使用 Terminal，Windows 使用 PowerShell 或 WSL。
- 事先申請 OpenAI 或 Anthropic 的 API Key。
- 確認自己有權限在本機安裝工具。
- 若公司設備有限制，先確認是否能執行下載腳本與寫入設定檔。

## 教學流程

### 第一階段：開場與環境確認（5 分鐘）

**階段目標**：讓全班在正式安裝前先確認終端機、網路與 API Key 都已就緒。

#### 步驟 1：確認終端機可正常輸入

**操作指令**

```bash
echo hello
```

**講授要點**

- 這一步不是在測 Hermes，而是在確認終端機能正常執行基本指令。
- 若連這一步都無法完成，後面的安裝會更容易卡住。
- 講師可順手觀察學員是用 macOS Terminal、iTerm2、PowerShell 還是 WSL。

**講師提示**

- 若有學員不熟終端機，先協助他分辨「可輸入指令的視窗」與一般文字編輯器的差別。
- 若學員使用公司配發電腦，這時就要先問有沒有安裝權限。

#### 步驟 2：確認 API Key 與網路狀態

**講授要點**

- 本單元需要可用的 API Key，沒有 Key 就無法完成後續設定。
- 若學員還沒準備好，先使用講師提供的備用 Key 完成流程。
- 提醒學員不要把 API Key 投影到大螢幕上。

**講師提示**

- 可請全班用舉手方式快速回報：終端機 OK、網路 OK、API Key OK。
- 若超過 20% 學員卡在同一步，不要急著往下走。

### 第二階段：安裝 Hermes（12 分鐘）

**階段目標**：完成 Hermes 安裝，讓 `hermes` 指令可在終端機中使用。

#### 步驟 1：執行安裝指令

**操作指令**

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

**講授要點**

- 這行指令會下載 Hermes 的安裝腳本並直接執行。
- 正常情況下，安裝只需要幾分鐘。
- 安裝完成後，系統會把 `hermes` 指令加入可執行路徑。

**講師提示**

- 請學員先不要急著複製第二條指令，先等安裝完成。
- 若現場網路較慢，講師可以先用自己的畫面示範一次完整流程。
- Windows 學員若使用 PowerShell，畫面與 macOS 可能略有不同，但流程概念相同。

#### 步驟 2：處理安裝常見狀況

**講授要點**

- 安裝階段最常見的問題是網路、權限、路徑沒有刷新。
- 不需要每個錯誤都深入解釋，先用最短路徑讓學員進到可操作狀態。

**常見問題處理**

| 問題 | 可能原因 | 建議處理方式 |
|------|----------|--------------|
| `curl: command not found` | 系統沒有 curl | 改用已安裝 curl 的終端機環境，或請助教協助安裝 |
| 安裝腳本下載失敗 | 網路不穩、公司防火牆 | 改用手機熱點或講師預先準備的備援方式 |
| 權限不足 | 公司設備限制、目錄不可寫 | 改用有權限的使用者環境，必要時先觀摩同組同學操作 |
| 安裝後找不到 `hermes` | 路徑尚未刷新 | 關閉終端機重開，或重新載入 shell 設定 |

**講師提示**

- 若只有少數學員卡住，不要讓全班一起等待太久。
- 可採「先完成的人協助旁邊同學」的節奏，維持教室流動。

---

### 第三階段：完成初始設定與驗證（10 分鐘）

**階段目標**：讓學員完成 `hermes setup`，並確認 Hermes 已可正常使用。

#### 步驟 1：執行初始設定

**操作指令**

```bash
hermes setup
```

**講授要點**

- `hermes setup` 會引導使用者完成第一次設定。
- 一般會包含模型供應商選擇、API Key 輸入、預設執行環境等項目。
- API Key 輸入時通常不會顯示字元，這是正常現象。

**講師提示**

- 提醒學員慢慢看提示，不要看到互動式畫面就一路按 Enter。
- 若學員不確定沙箱或執行模式怎麼選，先用預設建議值即可。
- 若畫面上出現成功訊息，請學員先不要關閉終端機。

#### 步驟 2：驗證版本與設定

**操作指令**

```bash
hermes --version
hermes config show
```

**講授要點**

- `hermes --version` 用來確認指令已成功安裝。
- `hermes config show` 用來快速檢查目前設定是否存在。
- 這兩個指令是課堂上最基本的健康檢查。

**講師提示**

- 若 `hermes --version` 有回應，代表安裝大致完成。
- 若 `hermes config show` 沒有顯示預期設定，可回頭再跑一次 `hermes setup`。

**預期產出**

- 學員終端機中可以成功執行 `hermes --version`。
- 學員完成至少一組有效的 Hermes 設定。

### 第四階段：建立第一個任務素材（6 分鐘）

**階段目標**：準備一份簡單、可立即看出效果的測試檔案。

#### 步驟 1：建立工作目錄與筆記檔

**操作指令**

```bash
mkdir -p ~/hermes-workshop
cat > ~/hermes-workshop/notes.txt << 'EOF'
週一：跟客戶 A 開會，討論 Q3 預算，客戶希望增加 20% 投入
週二：完成產品提案 v2 審核，有 3 處需要修改
週三：團隊 standup，小王提到 API 效能有問題需要排查
週四：客戶 B 來信詢問續約條件，回覆期限是下週一
週五：月報截止，需要彙整各組進度，重點標記落後項目
EOF
```

**講授要點**

- 這份檔案是 Hermes 的第一個處理素材。
- 用工作筆記做例子，是因為它貼近辦公室常見任務，也容易看出整理前後的差異。
- 學員不需要自己發明內容，先用同一份範例可以減少變因。

**講師提示**

- 若有學員不熟 heredoc 寫法，可請他直接複製貼上整段即可。
- 若個別學員貼錯內容，不用花太多時間修字句，只要檔案建立成功即可。

#### 步驟 2：快速確認檔案存在

**操作指令**

```bash
ls ~/hermes-workshop
```

**講授要點**

- 先確認 `notes.txt` 已經建立，避免下一步讓學員誤以為是 Hermes 出錯。
- 這也是在提醒學員：Agent 操作仍然建立在基本檔案與指令概念上。

---

### 第五階段：執行第一個 Hermes 任務（9 分鐘）

**階段目標**：讓學員第一次向 Hermes 下達具體任務，看到整理後的輸出檔案。

#### 步驟 1：進入互動模式

**操作指令**

```bash
hermes chat
```

**講授要點**

- `hermes chat` 會進入對話式操作模式。
- 這一段不是單純聊天，而是把自然語言轉成可執行任務。
- 接下來要觀察的重點不是答案漂不漂亮，而是 Hermes 怎麼完成工作。

#### 步驟 2：下達第一個整理任務

**操作內容**

```text
請讀取 ~/hermes-workshop/notes.txt，將內容整理成：
1. 一份條列式的本週工作摘要，按重要性排序
2. 一份待跟進事項清單，若有期限請標示
3. 把結果存成 ~/hermes-workshop/summary.md
```

**講授要點**

- 這個任務包含三件事：讀取檔案、整理內容、輸出到新檔案。
- 這是最適合說明 Agent 基本價值的入門例子。
- 請學員留意 Hermes 執行時的訊息，看看它有沒有先讀檔、再分析、再寫檔。

**講師提示**

- 若 Hermes 會顯示使用工具或步驟摘要，請停下來讓學員看一下。
- 可當場提問：「它剛剛第一步做了什麼？為什麼不是直接回答？」

#### 步驟 3：查看輸出結果

**操作指令**

```bash
cat ~/hermes-workshop/summary.md
```

**預期產出**

學員應能看到一份整理後的摘要，內容通常會包含：

- 依優先順序排序的工作摘要
- 需要跟進的事項
- 帶有期限或提醒的待辦項目

**講授要點**

- 這一步要讓學員感受到：「原始筆記」已經被轉成「可交付的整理結果」。
- 就算不同學員的輸出措辭不完全相同，只要結構合理即可。

---

### 第六階段：回顧 Agent 基本節奏（3 分鐘）

**階段目標**：幫學員把剛才的操作和 Agent 概念連起來。

**講授要點**

- 剛剛的流程不是單一步驟，而是完整的工作鏈：
  1. 使用者描述任務
  2. Hermes 判斷需要哪些步驟
  3. Hermes 讀取檔案
  4. Hermes 整理內容
  5. Hermes 寫出結果
- 這就是本工作坊後續所有實作的基礎。
- 後面單元會再加入更多工具，但核心節奏不變。

**講師提示**

- 不需要在這裡展開太多理論，點到為止即可。
- 可用一句話收尾：今天不是先學很多指令，而是先建立「怎麼跟 Agent 合作」的感覺。

## 預期產出

完成本 Lab 後，每位學員至少應有以下成果：

- 可在終端機中執行 `hermes` 指令。
- 已完成 `hermes setup` 的基本設定。
- 已建立 `~/hermes-workshop/notes.txt` 測試檔案。
- 已透過 Hermes 產生 `~/hermes-workshop/summary.md`。
- 能口頭描述一次基本 Agent 操作流程。

## 常見問題處理

| 情境 | 講師建議應對 |
|------|--------------|
| 學員沒有 API Key | 先用講師備用 Key 完成課堂流程，課後再引導自行申請 |
| 安裝卡在少數人 | 先讓其他人繼續，卡住者改與同組同學共用畫面觀摩 |
| 學員輸入指令時漏字或貼錯 | 不逐字糾正，直接提供可重貼的完整區塊 |
| `summary.md` 沒有成功產生 | 先確認 `notes.txt` 是否存在，再回頭檢查 Hermes 任務描述 |
| 學員問為什麼每台電腦結果不完全一樣 | 說明模型輸出本來就可能有差異，重點是流程與結果是否合理 |
| 現場網路不穩 | 切換熱點，必要時改成講師示範加學員觀摩 |

## 關鍵概念

| 概念 | 說明 |
|------|------|
| Hermes 安裝 | 先把工具裝好，Agent 才能在本機環境中執行 |
| 初始設定 | 透過 `hermes setup` 連接模型供應商與執行環境 |
| 互動模式 | `hermes chat` 讓使用者用自然語言下達任務 |
| 任務素材 | 給 Agent 一份真實資料，比抽象問答更容易看出價值 |
| 基本操作節奏 | 描述任務、讀資料、整理內容、輸出結果 |
| 輸出檢查 | 不只看 Hermes 有沒有回答，也要看檔案有沒有真的產生 |

## 教學提示

1. **把安裝風險留在前半段處理。** 這個單元最容易拖時間的是環境問題，不是內容理解。前 15 分鐘若能順利過關，後面會很順。

2. **第一個任務要有明確輸入與輸出。** 學員剛接觸 Agent 時，不適合用太開放的提示。像「幫我整理 notes.txt 並存成 summary.md」這種格式最穩。

3. **不要把重點放在每個人輸出一模一樣。** 這不是比對答案的練習。只要結果結構正確、內容合理，就算成功。

4. **善用同儕支援。** 現場通常會出現「已完成的人很快，卡住的人很久」的情況。請先完成的學員協助同桌，節奏會比講師逐一排除更順。

5. **講師示範時要刻意停頓。** Hermes 執行任務的過程本身就是教材。不要只秀最後答案，要讓學員看到中間發生了什麼。

6. **把後續單元先埋鉤子。** 在結尾提醒學員：今天只是安裝與第一個任務，下一個 Lab 會開始接觸更多工具與更完整的流程。
