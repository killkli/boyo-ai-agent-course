# Lab 1：Hermes 安裝與基礎操作

## 基本資訊

- **單元名稱**：Lab 1：Hermes 安裝與基礎操作
- **適用課程**：Hermes Agent 全天實作工作坊
- **時長**：45 分鐘
- **型態**：Hands-on 實作
- **對應課表**：09:25–10:10
- **對應學習目標**：完成 Hermes 安裝與設定、執行第一個 Agent 任務、理解基本操作節奏

## 單元目標

完成本 Lab 後，學員應能：

1. 在自己的電腦上完成 Hermes 安裝與初始設定。
2. 使用 `hermes` 指令確認版本與設定是否正常。
3. 進入互動模式，向 Hermes 下達第一個整理任務。
4. 看懂一次基本的 Agent 操作流程：接收任務、讀取資料、整理內容、寫出結果。

## 教學流程

### 第一階段：開場與環境確認（5 分鐘）

**階段目標**：讓全班在正式安裝前先確認終端機、網路與 API Key 都已就緒。

#### 步驟 1：確認終端機可正常輸入

**操作指令**

```bash
echo hello
```

**學習重點**

- 這一步不是在測 Hermes，而是在確認終端機能正常執行基本指令。
- 若連這一步都無法完成，後面的安裝會更容易卡住。

#### 步驟 2：確認 API Key 與網路狀態

**學習重點**

- 本單元需要可用的 API Key，沒有 Key 就無法完成後續設定。
- 請注意不要把 API Key 投影到大螢幕上。

---

### 第二階段：安裝 Hermes（12 分鐘）

**階段目標**：完成 Hermes 安裝，讓 `hermes` 指令可在終端機中使用。

#### 步驟 1：執行安裝指令

**操作指令**

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

**學習重點**

- 這行指令會下載 Hermes 的安裝腳本並直接執行。
- 正常情況下，安裝只需要幾分鐘。
- 安裝完成後，系統會把 `hermes` 指令加入可執行路徑。

#### 步驟 2：處理安裝常見狀況

**學習重點**

- 安裝階段最常見的問題是網路、權限、路徑沒有刷新。
- 不需要每個錯誤都深入解釋，先用最短路徑進到可操作狀態。

**常見問題處理**

| 問題 | 可能原因 | 建議處理方式 |
|------|----------|--------------|
| `curl: command not found` | 系統沒有 curl | 改用已安裝 curl 的終端機環境 |
| 安裝腳本下載失敗 | 網路不穩、公司防火牆 | 改用手機熱點或其他網路環境 |
| 權限不足 | 公司設備限制、目錄不可寫 | 改用有權限的使用者環境 |
| 安裝後找不到 `hermes` | 路徑尚未刷新 | 關閉終端機重開，或重新載入 shell 設定 |

### 第三階段：完成初始設定與驗證（10 分鐘）

**階段目標**：讓學員完成 `hermes setup`，並確認 Hermes 已可正常使用。

#### 步驟 1：執行初始設定

**操作指令**

```bash
hermes setup
```

**學習重點**

- `hermes setup` 會引導使用者完成第一次設定。
- 一般會包含模型供應商選擇、API Key 輸入、預設執行環境等項目。
- API Key 輸入時通常不會顯示字元，這是正常現象。
- 請慢慢看提示，不要看到互動式畫面就一路按 Enter。
- 若不確定沙箱或執行模式怎麼選，先用預設建議值即可。

#### 步驟 2：驗證版本與設定

**操作指令**

```bash
hermes --version
hermes config show
```

**學習重點**

- `hermes --version` 用來確認指令已成功安裝。
- `hermes config show` 用來快速檢查目前設定是否存在。
- 這兩個指令是最基本的健康檢查。
- 若 `hermes --version` 有回應，代表安裝大致完成。
- 若 `hermes config show` 沒有顯示預期設定，可回頭再跑一次 `hermes setup`。

**自我檢查**

- 確認終端機中可以成功執行 `hermes --version`。
- 確認已完成至少一組有效的 Hermes 設定。

### 第四階段：建立第一個任務素材（6 分鐘）

**階段目標**：準備一份簡單、可立即看出效果的測試檔案。

#### 步驟 1：建立工作目錄與筆記檔

**操作指令**

```bash
mkdir -p ~/hermes-workshop
cat > ~/hermes-workshop/notes.txt << 'EOF'
週一：埔里中心課輔班 — 國小四年級數學，5 位學童出席。小翰進度正常，小芳需要額外時間理解分數概念。
週二：竹東中心課輔班 — 國中二年級英文，4 位學童出席。小杰英文閱讀進步明顯，建議調整至進階組。
週三：教學研討會 — 討論下學期教材更新方向，決議數學教材加入更多生活應用題。社工組通報小恩家庭狀況需持續關注。
週四：新埔中心課輔班 — 國小六年級自然，6 位學童出席。實驗課效果良好，學童參與度高。
週五：每週彙整 — 本週三個中心共服務 47 位學童，出席率 92%。下週重點：暑期課輔班招生、特教生小恩的個別學習計畫調整。
EOF
```

**學習重點**

- 這份檔案是 Hermes 的第一個處理素材。
- 用課輔中心工作紀錄做例子，是因為它貼近博幼基金會日常業務，也容易看出整理前後的差異。
- 不需要自己發明內容，先用同一份範例可以減少變因。

#### 步驟 2：快速確認檔案存在

**操作指令**

```bash
ls ~/hermes-workshop
```

**學習重點**

- 先確認 `notes.txt` 已經建立，避免下一步誤以為是 Hermes 出錯。
- Agent 操作仍然建立在基本檔案與指令概念上。

---

### 第五階段：執行第一個 Hermes 任務（9 分鐘）

**階段目標**：讓學員第一次向 Hermes 下達具體任務，看到整理後的輸出檔案。

#### 步驟 1：進入互動模式

**操作指令**

```bash
hermes chat
```

**學習重點**

- `hermes chat` 會進入對話式操作模式。
- 這一段不是單純聊天，而是把自然語言轉成可執行任務。
- 接下來要觀察的重點不是答案漂不漂亮，而是 Hermes 怎麼完成工作。

#### 步驟 2：下達第一個整理任務

**操作內容**

```text
請讀取 ~/hermes-workshop/notes.txt，將內容整理成：
1. 一份條列式的本週課輔工作摘要，按重要性排序
2. 一份待跟進事項清單，包含需關注的學童與待辦任務
3. 把結果存成 ~/hermes-workshop/summary.md
```

**學習重點**

- 這個任務包含三件事：讀取檔案、整理內容、輸出到新檔案。
- 這是最適合說明 Agent 基本價值的入門例子。
- 請留意 Hermes 執行時的訊息，看看它有沒有先讀檔、再分析、再寫檔。

#### 步驟 3：查看輸出結果

**操作指令**

```bash
cat ~/hermes-workshop/summary.md
```

**自我檢查**

你可以用以下方式確認結果是否合理：

- 檢查 `summary.md` 是否存在，且內容有依優先順序排序的課輔工作摘要
- 確認是否有需要關注的學童與待跟進事項
- 確認是否包含下週重點工作與提醒事項
- 即使措辭與他人不完全相同，只要結構合理即可

**學習重點**

- 這一步要感受到：「原始課輔紀錄」已經被轉成「可交付的整理結果」。
- 就算不同學員的輸出措辭不完全相同，只要結構合理即可。

---

### 第六階段：回顧 Agent 基本節奏（3 分鐘）

**階段目標**：幫學員把剛才的操作和 Agent 概念連起來。

**學習重點**

- 剛剛的流程不是單一步驟，而是完整的工作鏈：
  1. 使用者描述任務
  2. Hermes 判斷需要哪些步驟
  3. Hermes 讀取檔案
  4. Hermes 整理內容
  5. Hermes 寫出結果
- 這就是本工作坊後續所有實作的基礎。
- 後面單元會再加入更多工具，但核心節奏不變。

## 常見問題處理

| 情境 | 建議處理方式 |
|------|--------------|
| 沒有 API Key | 先借用備用 Key 完成流程，課後再自行申請 |
| 安裝卡住 | 先確認錯誤訊息，對照上方常見問題表處理 |
| 輸入指令時漏字或貼錯 | 直接重新貼上完整的指令區塊 |
| `summary.md` 沒有成功產生 | 先確認 `notes.txt` 是否存在，再回頭檢查 Hermes 任務描述 |
| 不同電腦結果不完全一樣 | 模型輸出本來就可能有差異，重點是流程與結果是否合理 |
| 網路不穩 | 切換熱點或其他網路環境 |

## 關鍵概念

| 概念 | 說明 |
|------|------|
| Hermes 安裝 | 先把工具裝好，Agent 才能在本機環境中執行 |
| 初始設定 | 透過 `hermes setup` 連接模型供應商與執行環境 |
| 互動模式 | `hermes chat` 讓使用者用自然語言下達任務 |
| 任務素材 | 給 Agent 一份真實資料，比抽象問答更容易看出價值 |
| 基本操作節奏 | 描述任務、讀資料、整理內容、輸出結果 |
| 輸出檢查 | 不只看 Hermes 有沒有回答，也要看檔案有沒有真的產生 |
