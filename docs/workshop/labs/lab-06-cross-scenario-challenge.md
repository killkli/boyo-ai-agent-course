# Lab 6：分組挑戰賽 — 跨場景整合

## 基本資訊

- **單元名稱**：Lab 6：分組挑戰賽 — 跨場景整合
- **時長**：40 分鐘
- **型態**：分組挑戰 + 限時實作 + 短講分享
- **建議分組**：4 組，每組 4–6 人
- **對應課程位置**：Hermes Agent 全天實作工作坊下午場最後一個實作單元
- **銜接前一單元**：延續 Lab 4、Lab 5 已完成的博幼基金會場景原型
- **對應學習目標**：整合不同場景的 Agent 能力、在限制時間內完成跨場景設計、清楚說明整合方案的價值與取捨

---

## 挑戰賽目的

這個單元把原本第 6 堂的「跨組合作挑戰」從彈性延伸活動正式提升為 40 分鐘的完整教學單元。學員不再只優化單一場景，而是要把前面做出的原型往前推一步，思考不同 Agent 能力如何組合，變成更完整的工作流程。

本單元的重點有三個：

1. **從單點自動化走向流程整合**：不是只解決一個任務，而是把兩種以上的工作情境串起來。
2. **練習跨組協作與方案取捨**：不同組別要交換做法、整合想法，並決定哪些功能先做、哪些先保留。
3. **用有限時間做出可說明的方案**：不追求功能做滿，而是要做出一個能展示核心邏輯的版本。

---

## 教學流程

### 第一階段：挑戰說明與任務配對（5 分鐘）

**講師要做的事**

- 說明這一輪不是從零開始，而是接續 Lab 4、Lab 5 的成果。
- 宣布挑戰規則：每組必須整合至少兩個場景的需求或能力。
- 提醒評分重點在整合邏輯、任務設計、成果表達，不在功能是否完美。

**學員要完成的事**

- 快速回顧自己組別前一單元的原型。
- 決定要整合的第二個場景能力。
- 確認這一輪的分工：操作、紀錄、測試、分享。

### 第二階段：跨組交流與方案定義（8 分鐘）

**進行方式**

- 每組派 1 人到另一組，用 2 分鐘說明自己原型的用途、工具、輸出格式。
- 回組後整理可以借用的能力，決定本組的挑戰題方向。

**講師引導問題**

- 你們目前的 Agent 輸入與輸出是什麼？
- 如果接到另一組的輸出，下一步可以做什麼？
- 哪一段流程最適合先整合成第一版？

### 第三階段：限時實作（20 分鐘）

**實作要求**

- 至少整合兩個場景。
- 必須明確定義輸入、處理步驟、輸出。
- 至少完成以下其中一種成果：
  - 可執行的提示詞流程
  - 可展示的檔案輸入輸出
  - 清楚可說明的 Agent 串接原型

**建議實作順序**

1. 先寫一句話版本的挑戰目標。
2. 列出資料從哪裡來、要經過哪些步驟、最後要產出什麼。
3. 補上提示詞、工具分工或檔案格式。
4. 用一組測試資料跑最小版本。
5. 記下卡住的地方與下一步可擴充方向。

### 第四階段：成果快分享（7 分鐘）

- 每組 1 分鐘說明：
  1. 整合了哪兩個場景。
  2. Agent 流程怎麼串起來。
  3. 目前做到哪一步。
  4. 如果再多 30 分鐘，下一個會補什麼。
- 講師用 3 句話內給回饋，聚焦在整合思路是否清楚。

## 挑戰題範例

以下範例提供講師出題或學員卡住時使用。講師可直接指定，也可讓各組自行選題。

### 範例 A：課輔中心週報彙整 × 課輔計畫進度監控

**題目描述**

把「課輔中心週報彙整 Agent」和「課輔計畫進度監控 Agent」整合成同一條流程。Agent 不只整理各課輔中心的回報，還要標記進度異常，最後輸出一份督導可直接閱讀的摘要。

**建議輸出**

- 課輔中心週報摘要
- 異常課輔計畫清單
- 建議追蹤事項

### 範例 B：教學會議記錄整理 × 學童家長來信分類

**題目描述**

把教學會議中提到的家長問題、待辦事項，接到學童家長來信分類流程。讓 Agent 能從會議記錄抓出後續要回覆的重點，並產出課輔老師可參考的回應方向。

**建議輸出**

- 教學會議待辦清單
- 家長議題分類表
- 建議回覆重點

### 範例 C：學童家長來信分類 × 課輔中心週報彙整

**題目描述**

讓 Agent 在整理課輔中心週報時，同步加入當週家長來信的分類結果，讓督導一眼看到課輔進度與家長回饋。

**建議輸出**

- 課輔進度摘要
- 家長來信熱點分類
- 當週需要優先處理的家長關切事項

### 範例 D：教學會議記錄整理 × 課輔計畫進度監控

**題目描述**

把教學會議中產生的行動項目自動轉成課輔計畫追蹤清單，再對照目前課輔計畫狀態，標記哪些待辦可能影響學童學習進度。

**建議輸出**

- 教學會議 Action Items 清單
- 課輔計畫風險對照表
- 建議提前處理的項目

## 評分標準

| 評分面向 | 比重 | 說明 |
|------|------|------|
| 整合完整度 | 35% | 是否真的結合兩個以上場景，而不是只把題目並排放在一起 |
| 流程設計清晰度 | 25% | 輸入、處理、輸出是否講得清楚，Agent 任務邏輯是否合理 |
| 實作完成度 | 20% | 是否做出可展示的原型、提示詞、檔案流程或測試結果 |
| 場景價值與可行性 | 10% | 是否貼近博幼基金會實際業務情境，未來是否有落地可能 |
| 分享表達 | 10% | 是否能在短時間內清楚說明設計選擇與限制 |

**評分補充原則**

- 只要整合邏輯清楚，即使功能未完成，也可以拿到不錯的分數。
- 如果設計很有想法，但實作卡住，要能清楚說明卡點與下一步。
- 如果只做單一場景優化，不列入本單元完整得分。

## 成果分享方式

### 小組快講格式

每組用 1 分鐘完成以下四點：

1. 我們整合的兩個場景是什麼。
2. 資料怎麼流動，Agent 在哪裡做判斷。
3. 目前完成了哪些輸出。
4. 這個方案最適合用在哪一類工作現場。

### 講師回饋方式

- 先指出亮點，再補一個最值得繼續優化的地方。
- 優先評論整合思路，不糾結小錯誤。
- 若兩組選了相近題目，可點出不同做法，讓全班比較設計取捨。

### 同儕觀摩重點

學員在聽其他組分享時，可以特別注意：

- 對方怎麼定義跨場景的界線。
- 對方怎麼安排 Agent 的輸入輸出。
- 哪些做法可以帶回自己原本的場景繼續改。

## 關鍵概念

| 概念 | 說明 |
|------|------|
| 跨場景整合 | 把原本分開處理的工作任務串成一條連續流程 |
| 輸入／輸出設計 | 先想清楚資料格式與交接方式，整合才不會卡住 |
| 最小可展示原型 | 在有限時間先做出能說明核心邏輯的版本 |
| 任務拆解 | 把大挑戰拆成可操作的小步驟，優先完成關鍵段落 |
| 協作分工 | 一組內同時有人操作、有人整理、有人測試，效率會高很多 |
| 方案取捨 | 時間不夠時，知道先保留哪個功能，比什麼都想做更重要 |

## 教學提示

1. **這個單元要快，不要講太滿。** 開場說明控制在 5 分鐘內，時間盡量留給學員討論和實作。

2. **提醒學員用前一單元成果當基底。** 有些組會想重做一個全新的題目，講師要拉回來，讓他們站在已有原型上整合，這樣才做得完。

3. **若學員卡住，就先縮小題目。** 不一定要把兩個場景完整串到底，只要先完成一段明確的資料流就可以，例如「教學會議記錄整理完後，自動產出一份待回覆家長議題列表」。

4. **講師巡場時不要直接給答案。** 先問三件事：你們的輸入是什麼？中間要判斷什麼？最後要輸出什麼？多數卡關其實是流程沒講清楚。

5. **分享環節要守時。** 每組只有 1 分鐘，講師要明確提醒時間到就收，不然會壓縮到後面的成果展示單元。

6. **把重點放在思考方式。** 這個單元的價值不只是做出一個原型，而是讓學員看到 Agent 方案可以模組化、可以串接、可以擴充。

## 講師備註

- 本單元正式承接原第 6 堂的「延伸活動：跨組合作挑戰」，不再視現場時間彈性決定是否進行。
- 若上午或前一單元進度落後，可把「跨組交流」縮成 4 分鐘，「成果快分享」縮成 4 分鐘，但「限時實作」建議至少保留 20 分鐘。
- 若班級程度較強，可要求各組在分享時補充一段：如果要真的部署到公司流程，還需要補哪些工具或權限設定。
