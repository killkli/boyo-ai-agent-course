# Lab 2：工具系統深度探索

## 基本資訊

- **單元名稱**：Lab 2：工具系統深度探索
- **對應課程**：Hermes Agent 全天實作工作坊
- **時長**：50 分鐘
- **型態**：Hands-on Lab（講授 + 即時操作）
- **對應學習目標**：
  - W2.1 啟用並配置多種工具（搜尋、檔案、排程）
  - W2.2 設計需要串接多個工具的任務流程
- **承接關係**：延續 Lab 1 完成的 Hermes 安裝與基本操作，為 Lab 3 的自動化流程鋪路

## 課前準備

### 學員準備

- 已完成 `hermes setup`，可正常執行 `hermes chat`
- 筆電可連網，終端機可正常建立與查看檔案
- 已準備可用的 API Key

### 講師準備

- 確認現場至少有一台講師電腦可正常展示 `hermes tools` 相關指令
- 準備一份備用測試資料，供學員卡關時直接貼上
- 預先決定是否在課堂中啟用 `scheduler`，若環境不穩定可改為講師示範
- 準備 2–3 個安全機制討論題，方便帶到工具權限與確認流程

```bash
mkdir -p ~/hermes-workshop/lab2
cat > ~/hermes-workshop/lab2/notes.txt << 'EOF'
```

**講師提示**：這份資料刻意設計成「半結構化」文字，內容為博幼基金會的課輔工作待辦，方便後續示範讀取、整理、寫檔與排程。

## 單元目標

完成本 Lab 後，學員應能：

1. 看懂 Hermes 工具清單、工具用途與風險等級。
2. 啟用至少兩種工具，並觀察 Agent 如何決定呼叫順序。
3. 設計一個需要串接多個工具的任務。
4. 說出工具啟用時的基本安全原則，包括最小權限、確認機制與範圍限制。

## 教學流程

### 第一階段：工具系統總覽與風險分級（10 分鐘）

**目標**：先建立共同語言，讓學員知道「Agent 會做事」不等於「Agent 什麼都能做」。

#### 步驟 1：查看工具清單（3 分鐘）

**操作指令**

```bash
hermes tools list
```

**講授要點**

- 工具是 Agent 接觸外部世界的手腳。沒有工具，Model 只能生成文字。
- `hermes tools list` 的重點不是背工具名稱，而是看三件事：
  - 哪些工具已啟用
  - 哪些工具可啟用
  - 每個工具的風險等級與確認需求
- 可以把工具想成能力模組。搜尋、讀檔、寫檔、排程，本質上是不同的外部操作權限。

**講師提示**

- 不要一開始就把所有工具打開。先讓學員知道「開工具」本身就是設計決策。
- 若學員看到很多工具名稱感到混亂，提醒他們今天只聚焦三類：搜尋、檔案、排程。

#### 步驟 2：查看單一工具資訊（3 分鐘）

**操作指令**

```bash
hermes tools info web_search
hermes tools info file_write
```

**講授要點**

- `web_search` 代表「向外部找資料」的能力。
- `file_write` 代表「改變本機資料」的能力，風險通常高於純讀取。
- 同樣是工具，不同工具的風險來源不同：
  - 搜尋工具的風險是引用錯誤資訊
  - 寫檔工具的風險是覆蓋、誤寫、寫錯位置
  - 排程工具的風險是錯誤動作被重複執行

**講師提示**

- 可現場追問學員：「如果是 `file_delete`，你覺得風險會比 `file_write` 高還是低？為什麼？」
- 把風險討論拉回實際情境，不要停在抽象概念。

#### 步驟 3：建立安全觀念（4 分鐘）

**講授要點**

- 最小權限原則：任務只開需要的工具。
- 明確範圍原則：要指定檔案路徑、輸出位置與更新範圍。
- 先讀後寫原則：先看資料，再決定如何改動。
- 高風險工具需要確認：讓使用者保留最後決定權。

**講師提示**

- 可以用一句話收斂：「工具越多，Agent 能力越強；但控制不好，出錯成本也更高。」

### 第二階段：啟用單一工具並觀察 Agent 行為（10 分鐘）

**目標**：讓學員先看懂「單工具」怎麼被呼叫，再進入多工具串接。

#### 步驟 1：啟用搜尋工具（2 分鐘）

**操作指令**

```bash
hermes tools enable web_search
```

**講授要點**

- 啟用工具後，不代表每次任務都一定會用到。
- Agent 仍然會根據你的任務描述，自己判斷是否需要呼叫工具。

#### 步驟 2：測試搜尋與摘要（5 分鐘）

**Hermes 指令範例**

```text
請搜尋「AI 在課輔教學的應用」，整理 3 個重點，
每個重點用一句話說明，最後附上資料來源標題。
```

**講授要點**

- 這個任務看起來像一句話，其實至少包含三個子步驟：搜尋、閱讀、整理。
- 即使只有啟用一個工具，Agent 也會把任務拆成多步。
- 指令裡加入「附上資料來源標題」，是為了降低幻覺與摘要失真。

**講師提示**

- 引導學員觀察 Hermes 的過程輸出，不只看最後答案。
- 若搜尋結果品質參差，可示範追問：

```text
請只保留與課輔教學、偏鄉教育、學童學習支持相關的內容，重新整理。
```

#### 步驟 3：簡短回顧（3 分鐘）

**講授要點**

- 單工具任務已經會出現「任務拆解」；多工具任務則會再加上「工具編排」。
- 真正需要設計的是輸入限制與輸出格式，不是替 Agent 寫死每一步。

---

### 第三階段：檔案工具與本機資料操作（10 分鐘）

**目標**：把能力從「只會找資料」擴展到「能處理本機工作內容」。

#### 步驟 1：啟用檔案相關工具（2 分鐘）

**操作指令**

```bash
hermes tools enable file_read
hermes tools enable file_write
```

**講授要點**

- `file_read` 與 `file_write` 通常要成對思考。
- 只開寫入、不開讀取，很容易讓 Agent 在不理解上下文的情況下硬寫內容。

#### 步驟 2：執行讀取 + 整理 + 寫檔任務（6 分鐘）

**Hermes 指令範例**

```text
請讀取 ~/hermes-workshop/lab2/notes.txt，
把內容整理成一份 Markdown 課輔工作摘要，格式包含：
1. 待優先處理的工作項目
2. 需追蹤的學童與個案
3. 建議下一步行動
並存成 ~/hermes-workshop/lab2/summary.md
```

**講授要點**

- 這裡已經不是單純摘要，而是把原始文字轉成結構化輸出。
- `summary.md` 的路徑要明確指定，這是控制輸出範圍的一部分。
- 若沒有給格式，Agent 可能能做完，但結果較不穩定。

**驗證指令**

```bash
cat ~/hermes-workshop/lab2/summary.md
```

**講師提示**

- 如果環境不方便直接 `cat`，也可用編輯器打開檔案展示。
- 提醒學員：寫檔成功不代表內容一定符合需求，驗證是必要步驟。

#### 步驟 3：補充安全提醒（2 分鐘）

**講授要點**

- 避免只說「幫我整理一下並更新檔案」，最好指定檔名與輸出格式。
- 若是正式工作資料，先寫到新檔，再決定要不要覆蓋原檔。

---

### 第四階段：多工具串接練習（15 分鐘）

**目標**：把原本第 5 堂的「工具啟用」正式擴充成完整練習，讓學員實際設計工具流程。

#### 步驟 1：啟用排程工具（2 分鐘）

**操作指令**

```bash
hermes tools enable scheduler
```

**講授要點**

- `scheduler` 代表任務不只現在做，還可以未來重複做。
- 這類工具一旦設定錯誤，影響會被放大，所以更需要明確條件。

#### 步驟 2：講師示範完整串接任務（5 分鐘）

**Hermes 指令範例**

```text
請先搜尋「偏鄉教育數位化工具」，
整理成 3 點中文摘要，
再讀取 ~/hermes-workshop/lab2/notes.txt，
把搜尋重點和原本課輔待辦整合成一份 Markdown 檔案，
存成 ~/hermes-workshop/lab2/tool-safety-brief.md。
```

**講授要點**

- 這個任務至少串了三種能力：
  - `web_search`：補外部資料
  - `file_read`：取本機上下文
  - `file_write`：輸出整理結果
- Agent 的關鍵能力不是「工具很多」，而是「知道什麼時候用哪一個」。
- 若任務描述夠清楚，Agent 會自己規劃順序；若描述模糊，順序就容易亂掉。

**講師提示**

- 可以請學員先猜 Agent 會先搜尋還是先讀檔，再一起看實際執行。
- 若結果太長，可現場要求它重寫成更短版本。

#### 步驟 3：學員實作任務設計（6 分鐘）

請學員兩人一組，自行改寫成適合自己的版本。可直接提供以下挑戰題：

**挑戰題 A：課輔數位工具評估版**

```text
請搜尋「偏鄉教育數位化工具 2026」，
整理 3 個和課輔教學最相關的工具或平台，
再把結果寫成條列式 Markdown，
存到 ~/hermes-workshop/lab2/agent-updates.md。
```

**挑戰題 B：學童學習追蹤整合版**

```text
請讀取 ~/hermes-workshop/lab2/notes.txt，
再搜尋「課輔班學童學習追蹤 best practices」，
把搜尋到的做法套用到原本的課輔待辦內容，
輸出成一份更清楚的學童追蹤清單，
存到 ~/hermes-workshop/lab2/action-list.md。
```

**講師提示**

- 鼓勵學員自己改路徑、改主題、改輸出格式。
- 如果學員只會複製指令，追問他：「你想讓 Agent 多做哪一步？」

#### 步驟 4：快速分享（2 分鐘）

**講授要點**

- 請 1–2 組口頭說明自己的任務設計。
- 重點不是誰寫得最長，而是誰把條件講得最清楚。

---

### 第五階段：安全機制討論與收斂（5 分鐘）

**目標**：讓學員知道多工具不是炫技，而是需要邊界管理。

#### 討論題

1. 如果 Agent 可以寫檔，也可以排程，那最怕出什麼錯？
2. 如果搜尋到的資料品質不好，寫進內部文件會有什麼後果？
3. 如果要把今天的流程搬進公司環境，哪些工具你不會第一天就打開？

#### 講授要點

- 多工具串接最常見的錯誤不是「不會做」，而是「做太多」。
- 安全機制至少要包含：
  - 工具白名單
  - 高風險操作確認
  - 明確輸入與輸出路徑
  - 可回頭檢查的產出檔案
- 在真實辦公室場景裡，安全設計通常比提示詞文案更重要。

**講師提示**

- 最後用一句話收斂：「先讓 Agent 做可逆的事，再慢慢交給它做不可逆的事。」

| 階段 | 學員可見產出 |
|------|--------------|

## 關鍵概念

| 概念 | 說明 |
|------|------|
| 工具系統 | Agent 呼叫外部能力的機制，包含搜尋、讀檔、寫檔、排程等 |
| 工具啟用 | 讓原本只能對話的 Agent 取得新的操作能力 |
| 多工具串接 | 一個任務內依序呼叫兩種以上工具完成工作 |
| 工具編排 | Agent 根據任務需求決定先後順序與呼叫次數 |
| 最小權限原則 | 只啟用任務真的需要的工具 |
| 確認機制 | 高風險操作前保留人工核准步驟 |
| 可逆與不可逆操作 | 可逆如寫新檔，不可逆如刪檔或覆蓋正式資料 |

## 教學提示

1. **先讓學員看懂，再讓他們自己設計**。如果一開始直接丟多工具挑戰，很多人只會照抄，不會理解。
2. **不要把安全議題留到最後一句帶過**。本 Lab 的價值不只是會開工具，而是知道什麼情況不該開。
3. **路徑要寫明確**。學員最容易卡在找不到檔案或不知道檔案寫去哪裡。
4. **搜尋結果品質會波動**。若外部資料不穩，重點放在工具流程與驗證方法，不必執著每個人都得到同樣內容。
5. **排程工具可視現場狀況調整**。若時間吃緊，可改成講師示範，學員先理解概念即可。
6. **多工具任務的好壞，取決於限制條件是否清楚**。鼓勵學員在指令裡加上輸出格式、來源要求與檔案位置。
