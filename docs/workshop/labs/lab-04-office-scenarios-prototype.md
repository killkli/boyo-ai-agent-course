# Lab 4：辦公室場景實作（一）— 從需求到原型

## 基本資訊

- **所屬課程**：Hermes Agent 全天實作工作坊
- **Lab 編號**：Lab 4
- **時長**：60 分鐘
- **型態**：分組實作
- **位置**：下午場第一個單元
- **銜接關係**：承接上午的 Hermes 安裝、工具使用與自動化流程練習，為 Lab 5 的迭代優化建立第一版原型
- **核心目標**：讓學員把一個博幼基金會的真實業務情境拆成可執行的需求，完成資料準備、流程設計與第一版可運作原型

## 分組與場景選擇

- 全班分為 4 組，每組 4–6 人
- 每組固定三個角色，必要時可一人兼任兩項：
  - **流程整理者**：負責釐清需求、整理工作步驟
  - **Hermes 操作員**：負責輸入任務、觀察 Agent 行為
  - **記錄與報告者**：負責記錄決策、整理 Demo 素材
- 四組各選一個場景，原則上 A／B／C／D 各一組，避免重複
- 若現場人數不足四組，不同小組可處理同一場景的不同版本，例如「基礎版」與「進階版」

### 場景分配原則

| 場景 | 主題 | 建議對象 | 核心能力 |
|------|------|----------|----------|
| A | 課輔中心週報彙整 | 想先從固定格式任務開始的小組 | 彙整、摘要、格式統一 |
| B | 教學會議記錄整理與待辦追蹤 | 熟悉跨段文字整理的小組 | 摘要、結構化、行動項目擷取 |
| C | 學童家長來信分類與回覆建議 | 對社工服務情境有感的小組 | 分類、判斷優先級、回覆建議 |
| D | 課輔計畫進度監控與異常提醒 | 想挑戰分析型任務的小組 | 比對、風險判讀、異常標記 |

## 教學流程

| 時間 | 階段 | 活動流程 |
|------|------|----------|
| 0–5 分鐘 | 任務說明與分組確認 | 確認組員分工與場景 |
| 5–15 分鐘 | 需求分析 | 拆解流程、定義輸入與輸出 |
| 15–20 分鐘 | 測試資料準備 | 準備範例資料或整理既有素材 |
| 20–50 分鐘 | 第一版原型實作 | 用 Hermes 完成第一版流程 |
| 50–60 分鐘 | 結果檢查與收斂 | 整理原型、記錄問題與下一步 |

### 本 Lab 的交付標準

每組在 60 分鐘結束前，至少要交出以下三項：

1. 一句話說清楚這個場景要解決的工作問題。
2. 一份可展示的第一版原型成果。
3. 一張簡短說明，列出輸入資料、處理步驟、輸出結果。

## 四個場景的操作指引

這四個場景的重點很一致：先把需求講清楚，先做出可運作版本。做完第一版後，再把還沒處理好的地方留給下一輪迭代。

> **背景說明**：博幼基金會（Boyo Social Welfare Foundation）由李家同校長於 2002 年創立，2025 年全台共有 17 處課輔中心，服務 2,412 位偏鄉弱勢學童。三大服務策略為教育支持、社工輔導、畢業生追蹤，目標是「教育脫貧，讓知識帶希望回家」。員工包括課輔老師、社工師、行政人員、特教老師。

> **隱私保護提醒**：這些場景涉及學童資料、家長通訊、個案記錄等敏感資訊。操作時請嚴格遵守以下規則：
> - **只使用課程提供的範例資料**，不要輸入任何真實的學童姓名、家長姓名或個案內容
> - 如果要測試家長來信分類，請自己編造信件內容，不要用真實信件
> - 如果不確定某筆資料是否敏感，就當作敏感資料處理
> - 記住：你輸入給 Hermes 的所有內容都會透過 API 傳送到外部伺服器

### 場景 A：課輔中心週報彙整

#### 場景目標

把各課輔班每週提交的學童學習進度，彙整成一份總部可以快速閱讀的課輔中心週報。重點不是做得很漂亮，而是先讓格式一致、重點清楚、學童狀況一目了然。

#### 建議拆解方式

- 使用者是誰：課輔中心行政人員、基金會教育處
- 輸入是什麼：各課輔班老師提交的學童學習進度文字
- 輸出是什麼：一份統一格式的課輔中心週報
- 成功標準：能快速看出各班進度、學童個別狀況、需要特別關注的項目

#### 建議使用的工具

- `file_read`：讀取各課輔班的進度檔案
- `file_write`：輸出彙整後的週報

#### 實作步驟

1. 先決定週報欄位（班級名稱、本週進度、學童出席狀況、特殊事件），不要一開始就追求排版。
2. 讓 Hermes 先做「逐班彙整」，再做「跨班摘要」，不要一次塞太多要求。
3. 若各班回報格式差異很大，先要求 Agent 按相同欄位重新整理，再合併。
4. 若時間還夠，再補上整體摘要與需追蹤事項。

### 場景 B：教學會議記錄整理與待辦追蹤

#### 場景目標

把教學研討會的討論內容轉成兩種成果：一份能回顧討論脈絡的會議摘要，一份能追蹤責任與時程的待辦清單。

#### 建議拆解方式

- 使用者是誰：課輔中心教學組長、課輔老師、社工師、特教老師
- 輸入是什麼：教學研討會的討論記錄（含教材調整、個案討論、師資培訓）
- 輸出是什麼：會議摘要、Action Items、待追蹤個案
- 成功標準：讀完後知道誰要做什麼、何時完成、哪些學童需要後續關注

#### 建議使用的工具

- `file_read`：讀取會議記錄檔案
- `file_write`：輸出結構化的會議摘要與待辦清單

#### 實作步驟

1. 先區分「討論內容」與「需要追蹤的行動項目」。
2. 要求 Hermes 為每個待辦補上負責人、期限、優先順序。
3. 若原始紀錄沒有明確期限，可要求 Agent 標示「待確認」，不要假設。
4. 若時間允許，可再加上個案追蹤的相依關係或風險提醒。

### 場景 C：學童家長來信分類與回覆建議

#### 場景目標

讓 Hermes 幫忙做第一輪家長信件分流，先分清楚類型、緊急程度與回覆方向，減少社工人員從零開始判讀的時間。

#### 建議拆解方式

- 使用者是誰：課輔中心社工
- 輸入是什麼：家長或社區人士的來信或訊息
- 輸出是什麼：分類結果、優先級、回覆建議
- 成功標準：社工看到結果後，能決定誰先處理、怎麼回

#### 建議使用的工具

- `file_read`：讀取家長來信檔案
- `file_write`：輸出分類結果與回覆建議

#### 實作步驟

1. 先定義分類標籤：課程詢問、學童狀況反映、家長求助、資源申請、感謝回饋。
2. 優先級規則要講清楚，例如涉及學童安全或身心狀況的來信要提高處理等級。
3. 回覆建議先寫重點，不必一開始就生成完整回信。
4. 若同時處理多封信，要求輸出用表格或固定欄位，方便比較。

### 場景 D：課輔計畫進度監控與異常提醒

#### 場景目標

把基金會各項課輔計畫的執行狀態整理成一份能快速辨識風險的監控結果。這個場景的重點是比較，不只是摘要。

#### 建議拆解方式

- 使用者是誰：基金會教育處專員
- 輸入是什麼：多個課輔計畫的進度資料、里程碑狀態、風險描述
- 輸出是什麼：健康度判斷、異常清單、提醒建議
- 成功標準：能一眼看出哪個計畫需要先處理

#### 建議使用的工具

- `file_read`：讀取各計畫的進度檔案
- `file_write`：輸出監控報告

#### 實作步驟

1. 先訂健康度規則，例如正常、注意、警示、危險。
2. 要求 Hermes 說明判斷原因，避免只丟結論。
3. 先做單次分析，不必急著做成完整監控系統。
4. 若資料量偏大，先只處理 2–3 個計畫，確保比較邏輯成立。

| 概念 | 說明 |
