## 教學目標

完成本單元後，學員應能：

## 教學流程

### Step 1：從單次任務轉成工作流（10 分鐘）

**目標**：讓學員先理解自動化不是「多下一次指令」，而是先把流程拆清楚。

#### 學習重點

- 單次任務通常只解決眼前一次需求。
- 自動化工作流要先定義四件事：
  1. 何時觸發
  2. 讀哪些資料
  3. 做哪些處理
  4. 產出到哪裡
- 真正能落地的流程，輸入與輸出都要固定。
- 自學習迴圈不是魔法。前提是任務類型夠穩定，Agent 才能把成功路徑留下來。

#### 操作指令

先確認資料夾與測試檔案存在：

```bash
ls ~/hermes-workshop/lab3
```

進入 Hermes：

```bash
hermes chat
```

在 Hermes 對話中輸入：

```text
請讀取 ~/hermes-workshop/lab3/inbox-notes.txt，先不要直接寫檔，先幫我把這份課輔中心回報整理流程拆成四段：
1. 觸發條件
2. 輸入資料
3. 處理步驟
4. 輸出結果

情境是：我要每天下班前自動整理一份「當日課輔中心回報摘要與明日待辦」。
```

#### 自我檢查

你可以用以下方式確認流程草稿是否合理：

- 流程是否包含觸發條件、輸入資料、處理步驟、輸出結果四個部分
- 每個部分是否都有明確的描述
- 如果 Hermes 直接開始寫檔，可重新下指令，要求先做流程設計

---

### Step 2：建立第一版自動化摘要流程（15 分鐘）

**目標**：完成一次可運作的工作流，讓學員看見「讀取 → 分析 → 寫入」完整串接。

#### 學習重點

- 自動化的第一版先求可運作，再談優化。
- 輸出格式要固定，之後才容易比對差異、加入排程、做第二輪學習。
- 在辦公室場景裡，最常見的起點不是很複雜的 Agent，而是穩定的整理流程。

#### 操作指令

在 Hermes 對話中輸入：

```text
請讀取 ~/hermes-workshop/lab3/inbox-notes.txt，整理成一份課輔中心回報摘要，並寫入 ~/hermes-workshop/lab3/daily-summary.md。

格式要求：
- 第一段：今日各中心回報重點摘要（3 點內）
- 第二段：需要明天跟進的待辦事項
- 第三段：有截止壓力或需優先處理的事項
- 使用 Markdown 標題與條列
```

完成後，在終端機檢查結果：

```bash
cat ~/hermes-workshop/lab3/daily-summary.md
```

#### 自我檢查

- 確認 `daily-summary.md` 已存在，且內容包含至少三個區塊：各中心回報重點、明日待辦、截止與優先事項
- 若格式太亂，可補一句「請固定輸出成相同章節」重新執行
- 觀察 Hermes 是否主動先讀檔，再決定怎麼寫檔

---

### Step 3：加入排程，讓流程自動觸發（10 分鐘）

**目標**：把剛才的單次工作流改成定期執行任務。

#### 學習重點

- 排程是把 Agent 從「有人叫才做」變成「時間到就做」。
- 排程不是愈多愈好，先從固定、低風險、可驗證的工作開始。
- 好的排程任務要能說清楚：多久跑一次、要讀哪裡、更新哪個檔案。

#### 操作指令

如尚未啟用排程工具，可先執行：

```bash
hermes tools enable scheduler
```

再回到 Hermes 對話輸入：

```text
請建立一個排程任務：
- 每天下午 5:30 執行
- 讀取 ~/hermes-workshop/lab3/inbox-notes.txt
- 重新整理並覆蓋 ~/hermes-workshop/lab3/daily-summary.md
- 保留原本的三段格式：各中心回報重點摘要、需要明天跟進的待辦、有截止壓力的事項

建立後，請用簡短文字告訴我這個排程的觸發時間、輸入檔案、輸出檔案。
```

若 Hermes 支援排程清單，可再確認一次：

```bash
hermes tasks list
```

#### 自我檢查

- 確認已建立一個固定時間觸發的排程任務
- 能說出排程任務的輸入、輸出與更新頻率
- 若 `hermes tasks list` 沒有結果，以 Hermes 對話中的建立成功訊息為主

---

### Step 4：觀察自學習迴圈與技能累積（10 分鐘）

**目標**：讓學員理解 Hermes 如何把成功經驗變成可重用的技能。

#### 學習重點

- 自學習迴圈的核心不是模型改寫自己，而是保留有效做法。
- 類似任務重跑時，Agent 可能會少走幾步，因為它已經有可參考的成功路徑。
- 教學重點不是追求神奇效果，而是讓學員看懂「重用」這件事。

#### 操作指令

先建立第二份相似資料：

```bash
cat > ~/hermes-workshop/lab3/inbox-notes-day2.txt << 'EOF'
05/22 埔里中心回報：昨日缺席 3 位學童已聯繫家長，其中 1 位因家庭因素本週暫停課輔
05/22 竹東中心更新：新英文教材讀本已到貨 15 本，其餘預計下週三到貨
05/22 新埔中心彙整：家長座談會回饋已整理完成，多數家長希望增加戶外教學活動
05/22 暑期課輔班：目前三個中心合計報名 38 人，埔里中心已額滿，竹東與新埔尚有名額
EOF
```

回到 Hermes 對話輸入：

```text
請用和剛才相同的整理方式，讀取 ~/hermes-workshop/lab3/inbox-notes-day2.txt，輸出到 ~/hermes-workshop/lab3/daily-summary-day2.md。
```

接著查看技能：

```bash
hermes skills list
```

若想看單一技能內容，可再試：

```bash
hermes skills show
```

#### 自我檢查

- 確認已完成第二份摘要檔案
- 比較第一次與第二次任務的差別：提示是否更短、執行是否更順、格式是否更一致
- 能說明自學習迴圈的三個步驟：執行、記錄、重用
- 「技能」比較像工作模板或最佳路徑，不是重新訓練整個模型

---

### Step 5：完成一個辦公室版完整自動化工作流（5 分鐘）

**目標**：把前面分散的動作收斂成一套可描述、可交接的流程。

#### 學習重點

- 真正可用的工作流要講得出用途、節奏、輸入、輸出。
- 如果要交給同事使用，流程說明要比提示詞更重要。
- 這一步是為下午的場景實作鋪路。

#### 操作指令

在 Hermes 對話中輸入：

```text
請把我剛才建立的流程整理成一份簡短工作流說明，格式包含：
1. 流程名稱
2. 使用情境
3. 觸發方式
4. 讀取的資料
5. 產出的檔案
6. 這個流程最適合解決哪一類重複工作
```

#### 自我檢查

- 確認自己有一套能說明的自動化工作流
- 能向他人解釋這個工作流的用途、輸入、輸出與觸發方式

## 完整工作流設計示例

以下為參考範例：

| 元件 | 設計內容 |
|------|----------|
| 流程名稱 | 每日課輔回報摘要 Agent |
| 觸發方式 | 每天 17:30 自動執行 |
| 輸入來源 | `~/hermes-workshop/lab3/inbox-notes.txt` |
| 核心處理 | 讀檔、萃取各中心回報重點、排序待辦、標示需追蹤學童與截止項目 |
| 輸出結果 | `~/hermes-workshop/lab3/daily-summary.md` |
| 延伸版本 | 加入缺席異常提醒、每週課輔彙整、總部週報版 |

## 關鍵概念

| 概念 | 說明 |
|------|------|
| 自動化工作流 | 把觸發、輸入、處理、輸出固定下來，讓任務可以重複執行 |
| 排程 | 依時間自動啟動任務，適合日報、週報、提醒類工作 |
| 固定輸出格式 | 讓每次產出可以比較、覆蓋、延伸使用 |
| 自學習迴圈 | Agent 記錄成功解法，下次遇到相似任務優先重用 |
| 技能累積 | 把做過且有效的流程整理成可再次使用的能力 |
| 工作流設計 | 不只下提示詞，而是先定義資料來源、步驟與交付格式 |
