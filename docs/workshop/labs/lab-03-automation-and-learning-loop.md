## 教學目標

完成本單元後，學員應能：

1. 說出「單次任務」與「自動化工作流」的差別。
2. 使用 Hermes 建立一個含有讀檔、整理、寫檔、排程的完整流程。
3. 觀察相似任務重複執行時，Agent 如何縮短步驟或重用既有技能。
4. 根據工作場景調整觸發條件、輸入資料與輸出格式。

## 教學流程

### Step 1：從單次任務轉成工作流（10 分鐘）

**目標**：讓學員先理解自動化不是「多下一次指令」，而是先把流程拆清楚。

#### 講授要點

- 單次任務通常只解決眼前一次需求。
- 自動化工作流要先定義四件事：
  1. 何時觸發
  2. 讀哪些資料
  3. 做哪些處理
  4. 產出到哪裡
- 真正能落地的流程，輸入與輸出都要固定。
- 自學習迴圈不是魔法。前提是任務類型夠穩定，Agent 才能把成功路徑留下來。

#### 操作指令

先確認資料夾與測試檔案存在：

```bash
ls ~/hermes-workshop/lab3
```

進入 Hermes：

```bash
hermes chat
```

在 Hermes 對話中輸入：

```text
請讀取 ~/hermes-workshop/lab3/inbox-notes.txt，先不要直接寫檔，先幫我把這份工作整理流程拆成四段：
1. 觸發條件
2. 輸入資料
3. 處理步驟
4. 輸出結果

情境是：我要每天下班前自動整理一份「當日工作摘要與明日待辦」。
```

#### 講師提示

- 引導學員先看 Agent 怎麼拆流程，不急著要答案漂亮。
- 如果 Hermes 直接開始寫檔，提醒學員重新下指令，要求先做流程設計。
- 強調這一步是在做「需求定型」，後面排程才不會亂掉。

#### 預期產出

學員應得到一份結構清楚的流程草稿，例如：

- 17:30 觸發
- 讀取 `inbox-notes.txt`
- 萃取重點、排序待辦、標示截止項目
- 輸出 `daily-summary.md`

---

### Step 2：建立第一版自動化摘要流程（15 分鐘）

**目標**：完成一次可運作的工作流，讓學員看見「讀取 → 分析 → 寫入」完整串接。

#### 講授要點

- 自動化的第一版先求可運作，再談優化。
- 輸出格式要固定，之後才容易比對差異、加入排程、做第二輪學習。
- 在辦公室場景裡，最常見的起點不是很複雜的 Agent，而是穩定的整理流程。

#### 操作指令

在 Hermes 對話中輸入：

```text
請讀取 ~/hermes-workshop/lab3/inbox-notes.txt，整理成一份工作摘要，並寫入 ~/hermes-workshop/lab3/daily-summary.md。

格式要求：
- 第一段：今日重點摘要（3 點內）
- 第二段：需要明天跟進的待辦
- 第三段：有截止壓力的事項
- 使用 Markdown 標題與條列
```

完成後，在終端機檢查結果：

```bash
cat ~/hermes-workshop/lab3/daily-summary.md
```

#### 講師提示

- 學員如果產出格式太亂，請他們補一句「請固定輸出成相同章節」。
- 提醒學員觀察 Hermes 是否主動先讀檔，再決定怎麼寫檔。
- 如果有學員問「這跟直接叫 AI 幫我整理有何不同」，回到重點：現在的目標是把流程固定，準備交給排程重複跑。

#### 預期產出

- 每位學員產出一份 `daily-summary.md`
- 檔案內至少有三個區塊：今日重點、明日待辦、截止事項

### Step 3：加入排程，讓流程自動觸發（10 分鐘）

**目標**：把剛才的單次工作流改成定期執行任務。

#### 講授要點

- 排程是把 Agent 從「有人叫才做」變成「時間到就做」。
- 排程不是愈多愈好，先從固定、低風險、可驗證的工作開始。
- 好的排程任務要能說清楚：多久跑一次、要讀哪裡、更新哪個檔案。

#### 操作指令

如尚未啟用排程工具，可先執行：

```bash
hermes tools enable scheduler
```

再回到 Hermes 對話輸入：

```text
請建立一個排程任務：
- 每天下午 5:30 執行
- 讀取 ~/hermes-workshop/lab3/inbox-notes.txt
- 重新整理並覆蓋 ~/hermes-workshop/lab3/daily-summary.md
- 保留原本的三段格式：今日重點摘要、需要明天跟進的待辦、有截止壓力的事項

建立後，請用簡短文字告訴我這個排程的觸發時間、輸入檔案、輸出檔案。
```

若 Hermes 支援排程清單，可再確認一次：

```bash
hermes tasks list
```

#### 講師提示

- 如果現場工具版本不同，`hermes tasks list` 可能沒有結果。這時以 Hermes 對話中的建立成功訊息為主。
- 不要把這一步講成 DevOps。這裡教的是個人工作自動化，不是伺服器維運。
- 可順手點出常見場景：每日站會摘要、商機追蹤、客服回報整理、採購進度提醒。

#### 預期產出

- 學員建立一個固定時間觸發的排程任務
- 學員能說出排程任務的輸入、輸出與更新頻率

### Step 4：觀察自學習迴圈與技能累積（10 分鐘）

**目標**：讓學員理解 Hermes 如何把成功經驗變成可重用的技能。

#### 講授要點

- 自學習迴圈的核心不是模型改寫自己，而是保留有效做法。
- 類似任務重跑時，Agent 可能會少走幾步，因為它已經有可參考的成功路徑。
- 教學重點不是追求神奇效果，而是讓學員看懂「重用」這件事。

#### 操作指令

先建立第二份相似資料：

```bash
cat > ~/hermes-workshop/lab3/inbox-notes-day2.txt << 'EOF'
05/22 產品經理追蹤：報表欄位調整草案已完成，待主管確認
05/22 客服回報：兩位客戶仍在追問新版報表時程
05/22 業務更新：北區其中一筆商機已補登，下週需追另一筆
05/22 行政通知：週五前提交下月訓練需求
EOF
```

回到 Hermes 對話輸入：

```text
請用和剛才相同的整理方式，讀取 ~/hermes-workshop/lab3/inbox-notes-day2.txt，輸出到 ~/hermes-workshop/lab3/daily-summary-day2.md。
```

接著查看技能：

```bash
hermes skills list
```

若想看單一技能內容，可再試：

```bash
hermes skills show
```

#### 講師提示

- 引導學員比較第一次與第二次任務的差別：提示是否更短、執行是否更順、格式是否更一致。
- 若現場看不出明顯差異，直接用概念解說即可，不要硬說系統一定有學到。
- 說明「技能」比較像工作模板或最佳路徑，不是重新訓練整個模型。

#### 預期產出

- 學員完成第二份摘要檔案
- 學員能口頭說明自學習迴圈的三個步驟：執行、記錄、重用

---

### Step 5：完成一個辦公室版完整自動化工作流（5 分鐘）

**目標**：把前面分散的動作收斂成一套可描述、可交接的流程。

#### 講授要點

- 真正可用的工作流要講得出用途、節奏、輸入、輸出。
- 如果要交給同事使用，流程說明要比提示詞更重要。
- 這一步是為下午的場景實作鋪路。

#### 操作指令

請學員在 Hermes 對話中輸入：

```text
請把我剛才建立的流程整理成一份簡短工作流說明，格式包含：
1. 流程名稱
2. 使用情境
3. 觸發方式
4. 讀取的資料
5. 產出的檔案
6. 這個流程最適合解決哪一類重複工作
```

#### 講師提示

- 這份說明不一定要寫成檔案，但要讓學員能拿來對別人解釋。
- 若時間有餘裕，可請 2 到 3 位學員分享自己的工作流設計。

#### 預期產出

- 每位學員都有一套能口頭說明的自動化工作流
- 至少一組學員能分享實際工作上的套用場景

## 關鍵概念

| 概念 | 說明 |
|------|------|
| 自動化工作流 | 把觸發、輸入、處理、輸出固定下來，讓任務可以重複執行 |
| 排程 | 依時間自動啟動任務，適合日報、週報、提醒類工作 |
| 固定輸出格式 | 讓每次產出可以比較、覆蓋、延伸使用 |
| 自學習迴圈 | Agent 記錄成功解法，下次遇到相似任務優先重用 |
| 技能累積 | 把做過且有效的流程整理成可再次使用的能力 |
| 工作流設計 | 不只下提示詞，而是先定義資料來源、步驟與交付格式 |

## 教學提示

1. **先講流程，再講排程。** 很多學員一看到自動化就想立刻排時間，但如果流程本身還不穩，排程只會把錯誤重複放大。

2. **用真實辦公室語境帶入。** 這個單元最適合用日報、會議摘要、商機追蹤、客服整理等情境。學員會更快理解價值。

3. **不要把自學習講得太神。** 學員容易把它誤會成模型會自己進化。要說清楚：Hermes 主要是在累積成功路徑與技能模板。

4. **接受現場差異。** 不同版本、不同環境、不同工具權限下，技能清單與排程回饋可能不完全相同。只要核心流程能完成，就算達標。

5. **提醒資料與權限邊界。** 排程一旦啟用，代表 Agent 會定期碰觸指定資料。帶學員養成最小權限與固定資料夾的習慣。

6. **把這一堂當成下午實戰的前置訓練。** 上午學的是穩定流程，下午才進入場景組裝與優化。這樣節奏會順。
